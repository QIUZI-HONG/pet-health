# AI 降级的错误码与日预算：两条偏离交付文档的口径

交付文档 8.2 的错误码表里有两个 AI 专用的码：

| 码 | 文档要求 | 我们实际的做法 |
| --- | --- | --- |
| 60001 | AI 服务超时 → 可重试一次，仍失败转人工 | 降级：HTTP 200 + `degraded=true` + 一句保守中文 |
| 60002 | AI 分析失败 → 返回降级话术，不向用户报错 | 同上 |

文档 6.4 与 `docs/design/ai-service.md` 还提过「日预算熔断」（超限转纯规则通道 + 告警）。

## 一、60001 / 60002 不再使用，从错误码表里删掉

**决定：删除这两个码**（`ErrorCode` 与 `contract/common.yaml` 的错误码表一起删）。

理由：它们**从来没有产出路径**。降级一律是 HTTP 200 + `degraded=true`，用户看到的是一句按
`degrade_code`（`image_not_supported` / `image_unavailable` / `model_unavailable` /
`model_output_invalid`）映射的中文，不是错误码——这是 ADR-0021「医疗场景不向用户报错」的直接结果。
把永远不会出现的码留在契约里，等于让前端照着它写分支（文档要求的正是「可重试 / 转人工」两个分支），
而那两个分支永远不会被触发。真正的区分能力由 `degrade_code` 承担，且它已经落进留痕。

## 二、日预算只告警不熔断（接上 `ai.budget.daily-cny`）

**决定：本轮把预算接上，但只告警。** ADR-0025 已经定过口径（「记录 + 告警，不切断模型」，理由是当时
没有替代通道、50 元也是占位值），这一条是把那个决定落地：记录每次模型调用的 token 用量
（`ai_consult.prompt_tokens` / `completion_tokens`，含修复重试那几次），每小时按可配单价估算当日花费，
超预算**只记应用日志的 WARN**。

「运营能看到」这件事当前**只有应用日志这一个通道**（日志聚合后告警）；专门的监控与告警通道
属 #121 的「关键指标有监控与告警」验收项，不在这里重复造。

单价与预算是**占位值**，等 #119 的埋点跑出真实日用量再校准；「熔断后转什么通道」继续挂起——
在知识检索层落地之前，熔断等于把功能降级成固定话术（ADR-0025 的理由仍然成立）。

## Considered Options

保留 60001/60002：与文档一致，但要在契约里为两个永不出现的码写响应说明，且诱导前端写死分支。
按文档做熔断：现在没有替代通道、也没有真实用量数据，切掉模型等于把咨询功能变成固定话术。

## 三、护栏的药名表暂时留在代码里（对 ADR-0010 分层的显式例外）

ADR-0010 把「业务可调项」（提示词、红线词、分级规则、降级开关）放数据库、由运营后台改。
护栏的药名表（`ai/app/guardrails.py` 的 `DRUG_TERMS`）**属于这一类，但本轮仍留在代码里**：

- 它和红线词表是两类规则（红线是**短路**判红，护栏是**改写**输出），入库要一并设计 `kind`
  与动作语义，混进 `knowledge_red_flag` 会让那张表的含义变糊；
- 词表治理（增删、复核状态、谁有权改）正是 #103 要解决的问题，单独为它先造一张表
  只会做出一半。

因此这里记的是**一条有期限的例外**，不是「忘了分层」。落库时按 #103 的设计一起搬。

## Consequences

契约与实现一致：错误码表里剩下的都是**真的会出现**的码。代价是「拿交付文档逐条核对」时，
需要先说明这两条偏离（与 ADR-0001 ~ 0004 同样的处境）。

留痕表 `ai_consult` 多两列（`prompt_tokens` / `completion_tokens`），它们的用途不止计费：
模型换代、提示词改版、分级漂移的归因都要看用量曲线。
