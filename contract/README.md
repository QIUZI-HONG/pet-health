# 接口契约

**这里是接口的唯一源头。** 前端的 TS 类型由这里**生成**（`pnpm --filter @pet-health/shared gen:api`），前端不手写接口类型；后端 DTO **手写**，但必须与这里对齐（见 [ADR-0005](../docs/adr/0005-single-repo.md)）。

## 规则

- 先改 YAML，再改代码。改完跑一遍 `pnpm --filter @pet-health/shared gen:api` 重新生成前端类型；**CI 会校验生成物与契约是否同步**，不同步则构建失败。
- 公共组件（统一响应、错误码、分页参数）**只在 `common.yaml` 里定义一次**，各端用 `$ref` 引用，不复制。
- 按消费方分文件，路由前缀与之一一对应：

| 文件 | 前缀 | 消费方 | 状态 |
| --- | --- | --- | --- |
| `common.yaml` | — | 全部 | ✅ 已定义（统一响应 / 错误码 / 分页） |
| `provider.yaml` | `/api/v1/provider/**` | 服务者后台 | ⬜ 待定（等 #59 / #60 / #75 / #78） |
| `admin.yaml` | `/api/v1/admin/**` | 运营后台 | ⬜ 待定（同上） |
| `app.yaml` | `/api/v1/app/**` | C 端 | ✅ 账号 / 宠物 / 打卡 / 评分 / 防疫 / 消息 / 文件（切片 #94 #97 #99 #95） |
| `open.yaml` | `/api/v1/open/**` | 外部回调与签名直传 | ✅ 文件直传与读图（切片 #95，ADR-0020） |

## 为什么只有 provider / admin 还是空的

`common.yaml` 里的东西——统一响应结构、错误码表、分页规范——**不依赖任何未裁决的业务决策**（来源是交付文档 8.1 / 8.2），所以没有理由等它。C 端与 open 域按切片逐块落地：每张切片先改 YAML 再写代码，改了就跑生成。

服务者后台与运营后台仍是空的，因为它们的接口取决于地图上还没裁决的票：订单交易 #77、券池 #53、核销 #55、服务者入驻 #78、标准目录 #75、角色权限 #60……**现在写会返工**，所以只留了骨架与指向。

这个判断本身是有意的：契约优先的价值在于「先定不依赖决策的部分」，而不是「在决策未定时假装定了」。
