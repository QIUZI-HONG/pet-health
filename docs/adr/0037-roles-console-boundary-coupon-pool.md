# 第四批裁决：角色与权限、两个后台的边界、券池的领域模型

这三条都是「实现切片开工前必须定的口径」，各自挡住若干票，而且**互不依赖**（任一条改动都不影响另外两条）。合并成一份 ADR 的理由与 [ADR-0019](0019-reminder-system.md)、[ADR-0024](0024-quota-care-community-tracking-packages.md) 相同：拆成三份只会让索引更长。

## 一、角色与权限矩阵（挡 [#60](https://github.com/QIUZI-HONG/pet-health/issues/60) → #104 / #118 / #114）

**四个角色，落在三个登录域里**：C 端只有「用户」；服务者后台有「服务者管理员」与「技师」；运营后台有「运营」与「超级管理员」。

- **「付费用户」不是一个角色**——它是**权益**（[ADR-0036](0036-money-semantics-offline.md) 之后订阅没有支付载体，见 [ADR-0024](0024-quota-care-community-tracking-packages.md)）。交付文档 2.2 把它列成角色，是把「买过什么」和「能做什么」混在了一起；本项目按后者分角色。
- **「游客」也不是角色**：未登录就是没有身份，只读接口不需要身份（浏览服务目录与详情）。
- **技师是服务者管理员的权限子集**，同一人可同时持有两个角色（小店只有一个老板时他不会想开两个账号）。
- **交付文档里的「技师端」P029–P032 不另建端**：接宠检查 / 服务防护 / 取宠对比 / 报工是**服务者后台内、技师角色可见的服务流程**（CONTEXT.md 已把技师钉成服务者后台内的角色）。落点是订单进入「履约中」后的服务流程页面（ADR-0040 的三道照片墙），入口在「订单管理」与「服务标准」两处。

- 权限粒度是 **域 × 角色 × 资源归属**，落到接口鉴权上；资源归属不匹配一律 40400（docs/conventions.md，不泄露 id 是否存在）。

| --- | :-: | :-: | :-: | :-: |
| 维护门店信息与营业时间 | ✓ | ✗ | ✓（可干预） | ✓ |
| 选品 / 区间内定价 / 上下架 | ✓ | ✗ | ✗ | ✓ |
| 接单与派工 | ✓ | ✓ | ✗ | ✓ |

## 二、两个后台的功能边界（挡 [#59](https://github.com/QIUZI-HONG/pet-health/issues/59) → #104 / #118）

**服务者自治 + 平台守门**，跨边界的动作一律「**服务者发起 → 运营审批**」：

- **服务者自治**：门店信息、选品、区间内定价、上下架、接单派工、核销、报工、看自己的数据与考核。
- **平台守门**：目录增删、入驻与清退、券池模板与平台补贴券、考核规则、全平台数据、内容审核。
- **发起/审批的四个边界动作**：新项目申请（服务者提 → 运营审）、资质变更（服务者提 → 运营审）、目录项下架（运营发起）、服务者清退（超管执行，保留历史订单与档案、禁止新接单、已预约订单转取消）。
- 运营后台因此**不止交付文档画的四页**：至少还要有内容审核、考核规则配置、用户管理（只读）与系统配置（超管）。

两份后台的模块清单以各自的导航为准（服务者后台 11 个模块、运营后台 9 个），两个后台的界面骨架已按此建好。

## 三、券池的领域模型（挡 [#53](https://github.com/QIUZI-HONG/pet-health/issues/53) → #110 / #111 / #112 / #113）

**三个对象，定向发放**：

| 对象 | 谁创建 | 是什么 |
| --- | --- | --- |
| 券模板 CouponTemplate | **平台**（运营） | 券的定义：面额、门槛、有效期、适用范围、成本归属（provider_cost / platform_subsidy） |
| 券贡献 CouponContribution | 服务者 | 从券池里选一个模板并**承诺可核销额度**（total_count），不是发放实例 |
| 券实例 Coupon | 平台 | 发给某个用户的券。来源：邀请 / 打卡任务 / 积分兑换 / 平台补贴 |

- **服务者不能自建券模板**——「统一券池」是这个机制的核心卖点，放开自建等于没有券池。
- **不做抢券**：发放全部由任务、邀请、积分兑换与平台补贴**定向触发**（交付文档里也没有抢券场景）。
- **核销归属**：服务者贡献的券**只在其本店核销**；平台补贴券按模板的适用范围核销（不限店或限分类）。适用范围与标准目录项编码（[#75](https://github.com/QIUZI-HONG/pet-health/issues/75) 的两级目录）挂钩。
- **成本归属不产生资金**（[ADR-0036](0036-money-semantics-offline.md)）：`provider_cost` / `platform_subsidy` 只回答「这张券的抵扣算谁头上」，用于**核销统计与考核**（[#58](https://github.com/QIUZI-HONG/pet-health/issues/58)），不涉及结算与打款。
- **过期回退**：券过期未核销 → **释放服务者的贡献额度**（回到可核销池）；已核销不释放。余量按 `可发放 = total_count − 已核销 − 占用中（未过期未核销）` 计算，避免超发。
- **对账口径**（无资金流之后的对账，[CONTEXT.md](../../CONTEXT.md) 的对账条目）：券实例数 = 已发放 = 已核销 + 未过期未核销 + 已过期未核销；不平即告警。

## Consequences

- 交付文档 2.2 的七个角色收敛成四个，**「付费用户」这一列不落地**；「游客」不建角色。这条要与验收方说明。
- 服务者后台的「结算中心」按交付文档 P028 原样做不了（没有余额与提现）：退化为**对账视图**（流水与核销明细）。「营销中心」退化为**券与推广码**。
- 运营的「可干预接单」保留为运营的权限（矩阵里在「接单与派工」一列给的是 ✗，但运营的干预走**服务者清退与派单干预**两个独立动作，不占用日常接单权限）。
- 券的「一人一券」与反刷（同设备、同 IP）属 [#54](https://github.com/QIUZI-HONG/pet-health/issues/54) 与 [#121](https://github.com/QIUZI-HONG/pet-health/issues/121)，本 ADR 只定对象与额度口径。
