# 后端按领域分 Maven 模块，物理上单进程部署

交付文档第六章列了十个「服务」。本项目按领域拆 Maven 模块（`ph-account` / `ph-provider` / `ph-order` …），**但打包成一个进程部署**。

## Considered Options

- **十个独立微服务**：符合文档字面，但订单—核销—对账之间的跨服务事务需要补偿机制，部署与监控成本 ×10。
- **单模块按包分层**：上手最快，但十个域混在 controller / service / mapper 里，边界靠自觉，后期拆分要先理清依赖。

## Consequences

- 模块间只能通过接口或领域事件通信，**禁止 join 对方的表**。这条要靠构建期检查固化，不能靠自觉。
  - **例外（后加的）**：见 [ADR-0009](0009-ai-service-separate.md)——AI 服务直连 MySQL / Redis，**只读** `knowledge_*` 系列表。这是本条规则唯一的例外，写窄、只读、只限知识域。除它之外的任何直连都要先回来改这里。
- 拆分的触发条件先写死，避免日后拍脑袋：① 某模块资源占用显著高于其他；② 发布节奏互相阻塞；③ 某模块需要独立技术栈。
- 代价：跨模块调用比包内调用啰嗦，每个模块要显式定义对外接口。
