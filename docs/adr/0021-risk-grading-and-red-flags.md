# 风险分级：分级标准、硬红线落在哪、以及怎么证明它没退化

交付文档 F006 要求 AI 给出绿 / 黄 / 红三级，验收标准是「分诊准确率 ≥ 70%（0-6 月）」与「红色高危症状 100% 召回」；9.5 还要求 AI 绝不输出确诊、处方、用药剂量。这三条都指向同一件事：**分级不能全押给模型**。这一票定的是判据、硬红线的落点、以及验证方式。

## 决定

**一、三级判据按「就医紧迫程度」定义，不按病名**（CONTEXT.md 的 RiskLevel：它不是诊断结论）：

| 级别 | 判据 | 界面上的动作 |
| --- | --- | --- |
| 🟢 绿 | 无急症信号，可居家观察 | 给记录建议 + 观察要点；不给「没事」这类结论 |
| 🟡 黄 | 需要当面临床判断，但不必立刻急诊（症状持续、精神食欲下降、单次呕吐等） | 建议尽快就医；给就医前准备清单 |
| 🔴 红 | **任一硬红线命中**，或症状指向急症（窒息、抽搐、中毒、出血、呼吸困难、腹部膨大、无法站立等） | 立即急诊；给 24 小时医院入口 |

**二、硬红线命中即判红，不经模型**，且判据**入库**：

- 表 `knowledge_red_flag`（L1 结构化事实层，见 [63 号调研](../research/63-knowledge-base-rag.md) §1.1 的「红线规则表」）；
- 匹配在 **Python 服务**里做（`docs/design/ai-service.md` §1 的职责边界已经这么分），命中即返回红色结论并带上命中的词与规则，**不发起模型调用**；
- 放在 `knowledge_*` 命名下是有意的：[ADR-0009](0009-ai-service-separate.md) 允许 AI 服务只读 `knowledge_*`，这张表正好落在例外范围内，**不需要为它开第二个例外**；
- 词表是业务可调项（[ADR-0010](0010-ai-config-layering.md)），后续由 #103/#118 在运营后台维护，工程不写死在代码里。

**三、模型通道只负责「黄 / 绿」与解释**。红色由硬红线与模型共同产出，但**硬红线优先**：模型说绿、红线命中，按红返回。反过来（模型说红、无红线）也接受——那是模型更保守，安全方向允许。

**四、边界要求的落地方式是「两层」**（交付文档 9.5 的三个绝不：确诊 / 处方 / 用药剂量）：

- 提示词铁律（第一层，已在 `ai/app/prompts.py`）；
- **输出层校验**（第二层，本票新增）：模型返回的「可能原因 / 建议行动」过一遍禁用词与剂量模式（`\d+\s*(mg|ml|片|粒|mg/kg)` 这类），命中即**改写为「请遵医嘱」并把该条降级**，同时记 `guard_hits` 留痕——只靠提示词是赌，出了事没人知道是哪次漏的。

**五、评测集与测算方法**：

- 存放：`ai/tests/eval_set/*.yaml`，一条样本含 `text` + `species/age` + `expected_level` + `must_not_miss`（是否属于必须召回的高危）；
- 来源：**工程先按公开兽医急诊共识与交付文档 9.5 的四个高危症状（中暑 / 中毒 / 窒息 / 持续呕吐）构造首版**，每条注明出处；**标注由兽医复核后生效**——这一条本票做不完，明确记为缺口，不假装做完；
- 测算：`准确率 = 判对级别数 / 总数`；`红色召回率 = 实际红色且判红的条数 / 实际红色条数`。因为「红判绿」代价远高于「绿判红」（CONTEXT.md 的 EvalSet 条目），**回归门槛是召回率 100%、准确率 ≥ 70%**，任一不达标即拦发布；
- 运行方式：`pytest -m eval`（单独标记，需要真实模型，不进默认测试套），结果落 `ai/tests/eval_set/report-<日期>.md` 供人工核对。

## Considered Options

**分级全交给模型 + 调提示词**：实现最快，但「红色 100% 召回」这条验收标准就变成了一句期望——模型偶发漏判恰好落在最不能漏的地方（ADR-0017 已记录模型输出不稳定）。

**在 Java 侧做红线预检**：Java 拥有数据库、写起来也顺，但 `docs/design/ai-service.md` 已经把「硬红线匹配」划给 Python；挪到 Java 会让「分级逻辑在哪」这件事两处都有，且将来 #103 做灰度与提示词热更新时两边都要改。

**红线做成配置文件而非表**：省一次迁移，但 ADR-0010 明确要求业务可调项入库 + 运营后台可改；红线是**最需要现场增删**的一类规则（新毒物、新疫情）。

**用向量相似度做红线近似匹配**：能覆盖表达差异，但红色宁可多召回也不能漏——关键词命中是可解释、可复核、可追责的，本期先用它，近义表达靠词表里多写几个变体解决（词表的 `variants` 字段）。

## Consequences

「红色必带就医建议与免责声明」变成了可测的三段：硬红线短路（有测试）、输出层护栏（有测试）、评测集回归（门槛写死，但**首版标注待兽医复核**）。

分级标准这一版是按交付文档与公开共识推出来的，**不是兽医定稿**：其中「高频模糊症状」（呕吐 / 腹泻 / 精神不振 / 食欲下降）的归类必然有争议，所以这些样本的 `expected_level` 在评测集里标了 `provisional: true`，复核后改。这条比任何实现细节都重要——它决定了「准确率 70%」到底在跟谁比。
