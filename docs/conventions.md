# 项目级约定

来源：交付文档 13.2「默认决策表」与 13.3「开发纪律」。**遇到未明确的事项按这里执行，不要每处临时拍。**

**出处纪律**：下表条款来自交付文档，或本项目的约定（例如金额精度取 `decimal(10,2)`）。**凡没有明确标注 ADR 的，都不是 ADR 的要求**——ADR 只覆盖它自己写到的内容。引用前请回原 ADR 核对，别想当然。

⚠️ **与我们的 ADR 冲突时，ADR 优先。** 下表里带 ~~删除线~~ 或标注「已作废」的条款，是被 ADR 覆盖掉的——**不要照做**。原因写在各自的注里。

## 通用

| 项 | 约定 |
| --- | --- |
| 时区 | `Asia/Shanghai`（数据库、后端 Jackson、前端展示三处一致） |
| 日期 / 时间 | 展示 `YYYY年MM月DD日`；时间 `HH:mm` |
| 金额 | 单位元，保留 2 位小数，前端展示带 `¥` |
| 金额精度 | `decimal(10,2)`——与交付文档示例 DDL 一致。**禁止浮点** |
| 写操作留痕 | 所有写操作留 `operator_id` 与 `trace_id` |
| 手机号脱敏 | `138****8888` |
| 姓名脱敏 | `张*三` |
| 排序默认 | 时间倒序；评分、距离按场景 |
| 文案未指定 | 简洁直白，不超过 15 字；医疗警示用明确措辞 |

## 接口

| 项 | 约定 |
| --- | --- |
| 统一响应 | `{code, message, data, request_id}`，定义在 `contract/common.yaml` |
| 分页 | 每页 20 条，参数 `page` / `page_size` |
| ~~下拉刷新 + 上拉加载~~ | **已作废**（ADR-0001）：那是移动端手势，三个端都是桌面 Web，改用分页器 / 滚动加载 |
| 超时 | 15 秒，超时提示重试 |
| 重试 | **网络错误**自动重试 1 次；**业务错误不重试** |
| 缓存 | 列表 5 分钟、详情 1 分钟；**用户敏感字段不缓存** |
| Token 过期 | 静默用 Refresh Token 刷新；失败则跳登录 |
| 重复提交 | 按钮点击后禁用 2 秒；接口侧幂等用 `Idempotency-Key` 头，**口径已定**见 [ADR-0028](adr/0028-security-baseline.md)。**现状**：前端已按「请求进行中禁用」实现（更严）；接口侧幂等键**尚未实现**（口径已定，实现挂在 #121 的后续提交） |
| 错误码 | 见 `contract/common.yaml` 的 `x-error-codes`。**AI 降级不用错误码**：一律 HTTP 200 + `degraded` + 一句中文（[ADR-0026](adr/0026-ai-degrade-codes-and-daily-budget.md) 废弃了交付文档的 60001/60002） |

## 数据

| 项 | 约定 |
| --- | --- |
| 软删除 | 默认软删除（`is_deleted=1`）；**物理删除仅限账号注销场景** |
| 写操作留痕 | 所有写操作留 `operator_id` 与 `trace_id` |
| 数据库变更 | 必须写迁移脚本，可回滚 |
| 排序与索引 | 软删除字段默认过滤，且不影响索引使用 |

**这几条已经落成机制，写代码时照做即可**（实现细节见对应的 ADR，别每处临时拍）：

| 项 | 落点 |
| --- | --- |
| 主键、软删除、审计列、分页、小数与时间格式 | [ADR-0011](adr/0011-persistence-and-migrations.md) |
| 会话与令牌（Access 2h / Refresh 7d 存 Redis 可吊销） | [ADR-0012](adr/0012-auth-and-session.md) |
| 手机号等敏感字段的加密与等值查询 | [ADR-0013](adr/0013-field-encryption.md) |
| 测试打在真实 MySQL / Redis 上 | [ADR-0014](adr/0014-backend-test-strategy.md) |

两条最容易踩的：

- **取当前时间用 `AppTime.now()`**，不要用 `LocalDateTime.now()`（后者取 JVM 默认时区，本地/容器/CI 三个结果）。
- **越权一律返回 40400**，不要返回 40300——403 等于承认「这个 id 存在」。

## 开发纪律

- **提交信息**：`feat/fix/refactor/docs: 描述`。每个功能自测通过后再提交。
- **禁止硬编码**：配置走环境变量或配置表（分层见 [ADR-0010](adr/0010-ai-config-layering.md)）。
- **禁止吞异常**：必须记录日志并返回明确错误。
- **禁止跨层调用**：严格遵守分层架构（[ADR-0006](adr/0006-modular-monolith.md)）。
- **单元测试**：关键业务必须写，覆盖率 **≥ 60%**。
- **密钥**：只进本地 `.env`（已 gitignore）——不提交、不贴进对话、不写进文档。

## 与交付文档的对应关系

那份 13.2 的表是给「零提问开发」用的，所以它写得像绝对规则。但我们有一批 ADR 明确偏离了交付文档（ADR-0001 ~ 0004、0008、0009 是其中的偏离项）——**偏离处按 ADR 走**。哪四条在这里被覆盖：分页手势、视频尺寸、测试支付、4.2 色彩，上面都标了。
