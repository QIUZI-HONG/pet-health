# C 端桌面信息架构：左栏导航 + 多栏内容

C 端按 **1440px 基准**重排：左侧固定导航（5 个主页面）+ 顶部栏（宠物切换 / 通知 / 账号）；首页两栏；AI 管家 = 对话区 + 右侧信息栏。对应地图 [#65](https://github.com/QIUZI-HONG/pet-health/issues/65)。

视觉稿（`docs/assets/mockups/01_首页.png` 等五张）是按 420×836 手机尺寸画的，**布局整体重排，但颜色、字号、圆角、间距、图标沿用取色结果**（[ADR-0008](0008-tokens-from-mockups.md)）。

## Considered Options

- **顶部导航 + 多栏**：主内容区更宽、更像内容站。但顶部栏要同时塞下导航、宠物切换与通知，1440px 下很挤；且「服务 → 服务项」「档案 → 分项」这种两层结构在顶部导航里表达不出来。
- **单栏居中**（保留移动稿的纵向区块顺序，底部 Tab 换顶部导航）：改动最小、与稿子最接近。但首页在稿子上有 9 个纵向区块，原样搬到桌面就是一条长滚动页，桌面的大屏空间基本浪费。
- **左栏导航 + 多栏内容**（本决策）。

## Consequences

**移动端专属规范整体作废**（它们是手机形态的产物，不是设计语言）：

| 移动稿里的东西 | 桌面怎么处理 |
| --- | --- |
| 顶部状态栏（信号/电量） | 去掉——那是手机系统栏截图带进来的 |
| 底部 5 Tab 栏 | 换成左侧固定导航 |
| 底部安全区（`env(safe-area-inset-*)`） | 去掉 |
| 页面标题居中、单列纵向堆叠 | 标题左对齐；区块改多栏 |

**网格**：左栏 208px 固定；内容区左右留白 32px，最大宽度 1280px（超宽屏居中，不把卡片拉成一条线）。首页 = 主栏（评分 + 快捷服务 + 今日任务，占 2 份）+ 次栏（提醒流 + 券/邀请，占 1 份）；**AI 管家 = 对话区（占 2 份）+ 右侧信息栏（占 1 份）**，右栏常驻宠物摘要与风险提示——因为交付文档要求回答里有「风险等级 / 可能原因 / 建议行动」三段结构，那些结构化卡片需要常驻位置，不能全塞进气泡。断点：≥1280 两栏；1080–1280 收窄留白与栏宽；<1080 收成单栏（不做手机适配，见 [ADR-0015](0015-frontend-component-strategy.md)）。

**视觉验收的口径要改**：交付文档那条「与稿子肉眼无差异」是**照着移动稿写的**，桌面重排后逐像素对比不成立。可对照的是**取色与设计语言**：色值、圆角、间距、组件形态一致，布局按桌面重排。这条偏离记在这里，免得验收时被当成 bug。

**四种页面状态做成公共组件**（空态 / 加载 / 错误 / 无权限），任何页面拿数据都能直接套——验收标准里点名要复用。

**未登录不跳转、就地提示**：C 端是桌面 Web，用户可能直接打开一个深链接（比如从聊天里点开 `/records`）。这时保留框架、内容区显示「登录后查看」的无权限态并给一个登录按钮，比一把弹到登录页更友好，也顺手把无权限态用在了真实位置。
