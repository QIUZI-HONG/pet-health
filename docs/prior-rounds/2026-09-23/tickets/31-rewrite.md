## What to build

C 端前端的地基（**只依赖接口契约，不依赖后端是否就绪**，可与后端票并行开工）：

- **工程与脚本**：独立前端工程（Vue 3 + Vite + Vant 4）；`scripts/serve-app.sh`（容器内 dev，代理 `/api`，端口如 5174）与构建脚本；`vite.config.js` 与一期前端同构（proxy 目标可用环境变量覆盖）。
- **路由与框架**：底部 4 Tab（首页 / 档案 / AI 管家 / 我的）+ 二级页路由骨架；未登录拦截到登录页。**吸取一期教训**：后端不可用时要有明确提示，**不许白屏**。
- **请求层**：按接口契约封装（统一附加 token、统一错误码处理、401 与 429 的分流）。
- **设计系统**：交付文档第三卷的色彩 / 字号 / 圆角落成全局样式（主色 `#4CAF7D`、辅色 `#FF8A5C`、危险 `#FF6B6B`…）。
- **登录 / 注册页的界面**（表单 + 校验；协议勾选的位置预留，协议页与勾选逻辑在合规界面票）。

## Acceptance criteria

- [ ] `scripts/serve-app.sh` 起得来，手机浏览器（同局域网）可访问；`npm run build` 可出产物
- [ ] 底部 4 Tab 与二级页路由骨架齐备（页面内容可为空态）
- [ ] 未登录访问任意 Tab 落到登录页；登录 / 注册页表单渲染与校验正常
- [ ] 后端不可用时页面有明确提示、不白屏
- [ ] 请求层按契约就位（token 附加、401 回登录、429 有文案位）

## Blocked by
