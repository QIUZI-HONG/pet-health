# 多模态模型选型调研

> Issue: #61（父图 #52，阻塞 #69）
> 调研日期：2026-09-27
> 约束来源：[ADR-0004](../adr/0004-text-and-image-only.md)（只做文字 + 图片，语音转写后走文本，视频不做）、[ADR-0003](../adr/0003-lean-middleware.md)（保留向量检索，方案未定，见 #63）
> 硬指标：AI 问答 P95 < 3 秒；稳定输出结构化 JSON（`risk_level` / `possible_causes` / `action_suggestion` / `need_hospital` / `care_tips`）

---

## 0. 结论

**主力：阿里云百炼 `qwen3-vl-plus`；降本与预筛用 `qwen3-vl-flash`；`qwen3-vl-plus-2025-12-19` 快照。**

**备选（做 A/B，防单一供应商）：智谱 `GLM-4.6V`。** 输出价更低（3 元 vs 10 元/百万 Token），缓存命中折扣更大，且官方明确「首次在模型架构中将 Function Calling 原生融入视觉模型」。

**为什么是它们，而不是别人：**

1. **结构化 JSON 这件事上，唯一的稳妥路径是 function calling / tool call，不是 JSON mode。** 两家的一手文档都证实：**多模态输入下没有 schema 强约束**。阿里云明确写了「多模态输入（图像、视频、音频等）不支持 json_schema，会自动降级为 json_object，schema 约束不生效」。所以「稳定输出 5 个字段」必须靠我们自己兜：工具调用的参数 schema + 客户端校验 + 一次修复重试。这一点直接决定 #62 的评测集怎么建。
2. **图片理解能力不足以单独承载分诊，必须在产品上强制带症状文本。** VetClaw 的零样本实测：宠物皮肤病图片**纯图片** Top-1 仅 33.26%（Qwen3-VL-32B）/ 31.90%（InternVL3-38B）；**加上症状文本**后升到 72.17% / 94.34%（同一数据集，443 张图 4 分类）。宠病图 22 分类上纯图片 48.41% / 52.22%，加文本 84.02% / 88.11%。**这是本次调研里对产品设计最有杀伤力的一个数字**：不要设计成「拍张照就出诊断」。
3. **延迟上没有任何厂商公布 P95。** 「P95 < 3 秒」目前是不可验证的承诺。可行的做法见第 5 节：非思考模式 + 单次调用 + 图片降采样 + 流式首字，并自建压测。厂商能给的只有 RPM/TPM 限流。
4. **成本量级很低，不是瓶颈。** 10 万注册用户、按每天 3 次用满、走 flash 档，约 **1.05 万元/月**；走 plus 档约 **7.0 万元/月**。真实 DAU 下（按 30%）分别降到约 3,160 元 / 2.11 万元。

**顺带确认（供 #63 用）：** 阿里云有原生多模态向量模型 `qwen3-vl-embedding`，图片 1.8 元 / 文本 0.7 元每百万 Token，**同一个向量空间**——这对「用图片做 RAG 知识库检索」是关键能力。选 Qwen 的额外收益是 ASR（`paraformer` / `qwen3-asr`）、VLM、多模态 embedding 同一家，一张发票、一套合规材料。

**没搞定的：** 豆包（火山方舟）的价格**无法从一手来源核实**——`docs.volcengine.com` 是前端渲染的 SPA，抓不到正文。它很可能更便宜，建议在开工前补一次人工核对（见第 9 节）。

## 2. 结构化 JSON 输出的真实情况（本节最重要）

需求要求稳定输出 5 个字段。逐家核实一手文档后的结论是：**没有任何一家能在图片输入下做 schema 强约束。**

### 阿里云 Qwen

一手原文（[结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)）：

> 多模态输入（图像、视频、音频等）**不支持 json_schema，会自动降级为 json_object，schema 约束不生效。**

- **JSON Object 模式**：支持 Qwen 大部分模型，**明确包含 VL 系列**。用法 `response_format: {"type": "json_object"}`，但 prompt 里**必须出现「JSON」字样**，否则报错。
- **JSON Schema 模式**（`strict: true`）：仅限 **Qwen3.7-Plus / Qwen3.8-Flash / Qwen3.7-Flash / Qwen3.7-Max / Qwen3.8-Max** —— 全是**文本**模型。图片链路用不上。
- 另一个坑：非思考模型被强制用思考模式时，结构化输出「可能失效」；另外**不要设 `max_tokens`**，截断会直接产出非法 JSON。
- **Function Calling 在 VL 上是支持的**（[函数调用文档](https://help.aliyun.com/zh/model-studio/qwen-function-calling)）：多模态模型下列了「千问VL：Qwen3-VL-Plus 系列、Qwen3-VL-Flash 系列」，且文档里有**带 `image_url` 的多模态 User Message 示例**。也就是说：**带图的 tool call 是走得通的**，可以拿工具的 JSON Schema 当字段约束。

### 智谱 GLM

一手原文（[Z.AI 结构化输出文档](https://docs.z.ai/guides/capabilities/struct-output)）：

- **只记录了 `json_object` 一种模式**，页面里**完全没有出现 `json_schema`**。列出的支持模型是 `glm-5`、`glm-4.7`、`glm-4.5`、`glm-4.6`（原文 "etc."，非穷举）。
- 官方建议的做法是「在 system message 里描述期望的 JSON 结构」，然后在**客户端用 `jsonschema` 库校验**——等于官方承认约束在应用侧。
- 该页**没有提及图片输入或视觉模型**，因此「GLM-4.6V 支持 json_schema」这个说法**我无法证实**，搜索摘要里出现过，但一手页面不支持。**不要基于这个说法做设计。**
- 但 [GLM-4.6V 指南](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-4.6v) 明确列了 **Function Calling**，并称「首次在模型架构中将 Function Calling（工具调用）能力原生融入视觉模型」。所以 GLM 侧的稳妥路径同样是 **tool call**。

### 对工程的直接要求（给 #62 和实现阶段）

1. **用 tool call 承载 5 个字段**，不要用 `json_object` 裸输出。tools 的 `parameters` 写完整 JSON Schema（含 `enum` 约束 `risk_level`、`required`、`type: boolean` 约束 `need_hospital`）。
2. **客户端必须做三件事**：schema 校验 → 校验失败带错误信息重试一次 → 二次失败降级到保守结论（如 `risk_level` 拔高、`need_hospital: true`）并记指标。
3. **不要设 `max_tokens`**（阿里云明确警告），改用 prompt 约束长度。
4. **把「结构化输出成功率」做成上线指标**，和准确率并列。#62 的评测集必须包含「字段合法性」这一项，不能只测内容对不对。

## 3. 宠物相关判断场景的适配性

### 3.1 实测证据（这是本次调研的意外收获）

**VetClaw**（[arXiv:2607.26042](https://arxiv.org/abs/2607.26042)，2026-07，[HTML 全文](https://arxiv.org/html/2607.26042v1)）用 Qwen3-VL-32B 和 InternVL3-38B 做了**零样本**宠物疾病分类，这是目前最贴近我们场景的公开实测：

**Dogs Skin Disease Dataset（443 张图，4 分类）**

| 模型 | 纯图片 | 纯文本 | 文本 + 图片 |
|---|---|---|---|
| Qwen3-VL-32B | 33.26% | 69.00% | **72.17%** |
| InternVL3-38B | 31.90% | 100.00% | **94.34%** |

macro-F1：「from a macro-F1 score of 0.31 in the image-only setting to 0.69 macro-F1 in the text-image mode」。

**Pet Disease Images Dataset（1,736 张图，22 分类）**

| 模型 | 纯图片 | 纯文本 | 文本 + 图片 |
|---|---|---|---|
| Qwen3-VL-32B | 48.41% | 86.90% | 84.02% |
| InternVL3-38B | 52.22% | 86.04% | **88.11%** |

论文自己的告诫值得原样引用：**"we should use only fine-tuned VLMs for better results."**

**PetQA**（[arXiv:2609.04598](https://arxiv.org/abs/2609.04598)，EMNLP 2026）是韩语兽医长文本 QA 基准，10,076 条纯文本 + 8,751 条多模态问答，来自真实猫狗问题与执业兽医答案，评测 18 个模型。两个可用结论：**皮炎（dermatitis）在多模态子集中是最常见的病症之一**（说明皮肤问题天然依赖图片）；**所有模型在多模态题上都比纯文本题差**。

### 3.2 四条场景的适配性判断

按 ADR-0004 列的四个场景，结合上面的证据分开看——**模型能力差异很大，不要当一件事**：

| 场景 | 判断 | 依据与做法 |
|---|---|---|
| **皮肤病变** | **能用，但不能单靠模型**。零样本纯图片仅 33–52%，是四个场景里最难的 | 强制症状文本（问「痒不痒 / 掉毛多久 / 有没有结痂」）。NER 类细粒度任务另需专门模型：有工作用 ResNet50+CBAM + BERT 融合、50,000+ 张标注宠物皮肤图达到 **92.59%** 验证准确率（[IEEE 11517870](https://ieeexplore.ieee.org/document/11517870)，2026-05）——**细调窄模型显著优于通用 VLM**，这是后期准确率提升的主要杠杆（归 #62） |
| **耳道** | **风险最高**。耳道是深腔、需要耳镜/光照，手机外拍图质量通常不足以支撑判断 | 不建议做成「拍照出结论」。应当产出「外观可见部分的描述 + 建议线下检查」，把 `need_hospital` 的默认倾向调高 |
| **排泄物** | **相对最适合**。颜色/形状/质地的判断更接近视觉分类，且用户容易拍到清晰图 | 值得做，且可以设计成结构化选项（颜色盘、形状图例）+ 图片的组合，降低对模型自由判断的依赖 |
| **体态** | **适合做「变化趋势」而非单次判断**。单张照片判胖瘦受角度/毛量/品种影响极大 | 与「三道照片墙」和健康评分的连续记录结合，做同个体纵向对比，而不是跨个体绝对值判断 |

**核心结论：图片的价值是「补充文本难以表达的信息」，不是「替代文本」。** 产品上要把图片定位成辅助证据，而不是输入的全部。这同时是最有效的降本与降延迟手段。

### 3.3 能力自述（厂商侧）

- **GLM-4.6V**：支持图片 / 视频 / 文件；能力含视觉理解、工具调用、思考模式开关；128K 上下文，官方称「约等于 150 页复杂文档、200 页 PPT 或一小时视频」。**图片数量上限 ≤50 张**。
- **Qwen3-VL**：图片上限按传入方式区分——公网 URL / 本地路径最多 256 张（Qwen3.8/3.7 新一代到 2048 张），base64 最多 250 张。思考模式为混合型，`qwen3-vl-plus` / `flash` 默认 `false`（**这是延迟友好的默认值，生产环境保持关闭**）。
- 两家都没给宠物场景的任何官方能力说明。**宠物场景没有厂商背书，只有上面那几篇第三方实测。**

## 4. 延迟：P95 < 3 秒怎么落地

### 4.1 现状：不可验证

**没有任何厂商公布 P95 延迟或延迟 SLA。** 我把能查到的一手材料列出来，全部只到「限流」层级：

- 阿里云给的是 RPM/TPM（`qwen3-vl-plus` 北京 RPM 3,000 / TPM 5,000,000），**不给延迟**。
- 唯一的厂商延迟自述：`qwen3-vl-plus-2025-12-19` 快照相比 9 月版「更低的延时和更快的响应速度」，**无数字**。
- 第三方测得的 `qwen3-vl-plus` 延迟**互相矛盾**（一处约 1.04 s，另一处 vision API 实测平均 3.859 s）——来源不可靠，**我不采用，也不写进结论**。
- 唯一可信的定量锚点是 VetClaw：Qwen3-VL-32B 在 A100 80GB 上单次推理响应 **925.3 ms**。注意这是**自部署 32B**、且**不含图片上传时间**（同实验里上传到 Google Drive 单独耗了 1,977.86 ms，拍照 2,820.47 ms）。

**结论：P95 < 3 秒目前是一个假设，不是一个已验证事实。** 需要自建压测才能确认，见 4.3。

### 4.2 达成 3 秒预算的工程手段（按收益排序）

| 手段 | 收益 | 依据 |
|---|---|---|
| **关闭思考模式** | 最大单项。思考模式「最大思维链长度 81,920」，直接产生数千 token 的串行生成 | 阿里云模型页；且 `qwen3-vl-plus` 默认就是 `false`，别打开 |
| **图片降采样到长边 768–1024 px** | 图片 token 与像素成正比，直接压输入长度和视觉编码耗时 | 见下方 token 规则 |
| **单次调用，不要多轮** | 每多一轮就多一次完整往返。分诊不要做成 agent 多步 | — |
| **流式输出首字** | 感知延迟从「总时长」变成「首 token 时间」，用户可先看到 `risk_level` 流式出来 | Qwen / GLM 均支持流式 |
| **把静态前缀（system + 知识库）做上下文缓存** | GLM 缓存命中价 0.2 vs 1 元/M（省 80%）；阿里云亦有缓存折扣 | 两家价格页 |
| **图片先过一遍客户端压缩** | 顺带降上传时间——上传是上面 VetClaw 里最大的单项耗时 | VetClaw Table 2 |

### 4.3 必须补的验证动作

写进开工清单，**不要等上线才发现**：

1. 用**真实拍摄的宠物照片**（含手机原图、不同光线）压测 `qwen3-vl-plus` 与 `GLM-4.6V`，记录 P50 / P95 / P99 端到端（含上传）。
2. 分别在**思考模式开 / 关**下测一遍，量化差距。
3. 测图片长边 512 / 768 / 1024 px 三档的延迟与准确率权衡，选出产品默认值。
4. **把压测结果回填到 #62 的验收口径**——「P95 < 3 秒」如果不成立，需要重新谈这个指标（可能的方向：首字 < 1.5 秒 + 完整 < 5 秒，或对图片问答放宽）。

### 4.4 图片 token 规则（成本与延迟的共同分母）

一手事实与换算：

- **公式**：`图像 Token 数 = (缩放后高 × 缩放后宽) / 每 Token 像素数 + 2`（+2 是视觉起止标记）。
- **每 Token 像素数**：**Qwen3-VL 为 32×32**；旧 `qwen-vl-max`、`Qwen2.5-VL`、QVQ 系列为 28×28。
- **默认缩放区间**：`min_pixels = 3136`（≈4 Token）到 `max_pixels = 1003520`（≈**1280 Token**）。可用 `max_pixels` 调低。
- **高分辨率模式** `vl_high_resolution_images=True` 上限提到 **16384 Token**——**别开**，除非有明确的高精度 OCR 需求。
- 阿里云 API 响应里有 `image_tokens` 字段（文档示例值 1247 / 2497），**以实测为准**。
- 智谱侧：官方 FAQ 给出「GLM-4V 系列图像识别模型，单张图片约消耗 **1047 个 tokens**」，与阿里云默认上限同量级。

**本次成本模型采用的假设：单张图 1,300 Token**（≈ Qwen3-VL 默认上限 1280 + 2 个标记，并与智谱的 1047 同量级）。可通过降采样进一步压低。

### 5.3 选型结论

**首选 `paraformer-v2`（录音文件识别，0.00008 元/秒）。** 理由：

1. **是上面所有选项里最便宜的，比第二名便宜 2.75 倍**，比智谱的 GLM-ASR 便宜约 2.5 倍。
2. **C 端语音入口是「按住说话、松开上传」的形态，不是实时对话**——ADR-0004 已经砍掉了实时链路，走文件识别完全够用，没有理由付实时识别的 3 倍溢价。
3. **每月 36,000 秒免费额度**：在 1,000 用户规模下，即使 10% 的调用走语音、每次 15 秒，月耗 135,000 秒——免费额度覆盖约 27%。这个额度对小规模验证阶段基本等于免费。
4. 与 VLM、embedding 同属阿里云百炼，**一张发票、一套合规材料、一个 SDK**。

**备选 `fun-asr`**（0.00022 元/秒）：如果产品确定为**实时转写**（边说边出字），或 paraformer 在宠物术语（品种名、药名）上识别不佳时切换。**别用 `qwen-audio-3.1-asr-flash`** 的 Token 计费——按 Token 计价的 ASR 成本随转写文本长度增长，在长语音下不如按秒计价可预测。

**若为延迟敏感**：实时识别单价是文件识别的 3 倍（0.00024 vs 0.00008），但换来「边说边出字」的体验。ADR-0004 的语音是「转写后当文本发送」，**建议先做文件识别**，把实时留作后续可选项。

### 6.4 读法

- **10 万注册用户、走 flash 档、DAU 30%，约 3,159 元/月（≈3.8 万元/年）。** 这个量级对一个 C 端产品不构成财务压力。

- **建议的成本策略**：默认档走 `qwen3-vl-flash`；把 **plus 留给「风险分级」这条需要判断力的路径**，或用**图片质量 / 症状复杂度做路由**（简单问答走 flash，疑似高风险走 plus）。这个路由顺便还能压延迟。
- **视频不做（ADR-0004）省下的钱**：视频理解按帧计费，1 分钟 30fps 视频远超 256 张图上限。ADR-0004 的决策在本模型里已被验证为正确的成本决策。

| 规模 | 月语音秒数 | paraformer-v2 成本 | 免费额度覆盖 |
|---|---|---|---|
| 1 千用户（场景 A） | 135,000 秒 | **10.8 元**（免费额度覆盖 27%） | 36,000 秒 |
| 1 万用户（场景 A） | 1,350,000 秒 | **108 元** | 2.7% |
| 10 万用户（场景 A） | 13,500,000 秒 | **1,080 元** | 0.3% |

**语音成本相对图片链路可忽略**（约为 VLM 成本的 10%）。若改用实时识别（0.00024），10 万用户规模升至 3,240 元/月。

### 6.6 上下文缓存能再省多少

以 `GLM-4.6V` 为例，把 1,500 Token 的静态前缀（system + 知识库）做缓存：

- 不缓存：2,800 × 1 = 0.0028 元
- 缓存后：1,500 × 0.2 + 1,300 × 1 = 0.0003 + 0.0013 = **0.0016 元**（输入省 43%）

**前提是 prompt 结构必须把「静态前缀在前、动态内容在后」**——这是个必须现在就定下来的 prompt 结构约束，否则后期加缓存要重构。

## 7. 合规与开票

### 7.1 法定义务（一手，《生成式人工智能服务管理暂行办法》）

[国务院 2023 年第 15 号令全文](https://www.gov.cn/zhengce/zhengceku/202307/content_6891752.htm)：

> **第二条**：利用生成式人工智能技术向中华人民共和国境内公众提供生成文本、图片、音频、视频等内容的服务（以下称生成式人工智能服务），适用本办法。

> **第九条**：提供者应当依法承担网络信息内容生产者责任，履行网络信息安全义务。涉及个人信息的，依法承担个人信息处理者责任，履行个人信息保护义务。

> **第十七条**：提供具有舆论属性或者社会动员能力的生成式人工智能服务的，应当按照国家有关规定开展安全评估，并按照《互联网信息服务算法推荐管理规定》履行算法备案和变更、注销备案手续。

其他相关义务：第十条（公开适用人群、场合、用途，防范未成年人沉迷）、第十一条（保护输入信息与使用记录，不得收集非必要个人信息）、第十二条（按《深度合成管理规定》对生成的图片、视频**进行标识**）、第十四条（违法内容处置与报告）、第十五条（投诉举报机制）。

### 7.2 关键风险：调 API 不等于合规义务转移

**这是我们最容易踩的坑。** 从多个二手来源（网信办口径转载，口径一致）得到：

> 对于通过 API 接口或其他方式**直接调用已备案模型能力**的生成式人工智能应用或功能，由**地方网信部门开展登记**。

含义：

1. **厂商已经备案，不代表我们可以免责。** 我们作为面向公众的服务提供者，需要自行完成**大模型登记**（约 1–3 个月）。
2. **算法备案与大模型登记并行，不是二选一。**
3. **分界线在于我们是否对输出做「实质性修改」。** 如果我们在前端做内容过滤、重组、格式改写、安全审核——**可能被认定为实质性修改，从而从「登记」升级为「备案」**（约 6–8 个月）。

**第 3 条对我们有直接设计影响**：我们**本来就要**做 JSON 修复重试、字段兜底、风险等级拔高。这些动作是否构成「实质性修改」需要法务确认。**这是一个现在就要问的问题，不是上线前才问的。** 而且这个结论会反向约束 #62 的评测设计。

**第十二条的标识义务**也别忘了：AI 生成内容需要标识。我们的 JSON 结果是给用户看的问答内容，需要明确标注「AI 生成，仅供参考，不构成诊断」。

**诚实标注**：第 7.2 节全部来自二手转载，我**没有取得网信办原文页面**（`cac.gov.cn` 未能抓取到具体公告页）。**开工会前需人工核实一次**，或直接咨询属地网信办。

### 7.3 开票

- **智谱**：按**实际消耗金额**开票（不支持按充值金额开票），自助开票，3–7 个工作日发送到邮箱；账户欠费时欠费账单无法开票；**完成企业认证可开具企业专票**（GLM Coding Plan 团队版明确列出「集中式账单与发票管理」）。
- **阿里云**：可正常提供发票，需企业认证。
- **来源说明**：开票信息来自二手整理（含智谱官方文档的转述），**未逐条核对官方财务文档**。两家均为正规供应商，开票能力不是选型差异点，但**发票类型（专票 / 普票）与抬头需在企业认证时确认**。

**合规维度不构成选型差异**：阿里云、智谱、腾讯、Kimi 均为境内主体、均有已备案模型、均可开票。真正的合规工作量在我们的**登记**上，与选谁无关。

### 给 #63（分层知识库与 RAG）

**所选模型自带 embedding 能力，但更重要的是它有原生多模态向量模型。** 一手数据：

| 模型 | 图片输入 | 文本输入 | 备注 |

| qwen3-vl-rerank | — | — | 存在，配套重排 |

| 腾讯 Hunyuan-embedding | — | 0.7 / 0.7 元/百万 Token | 纯文本 |

**关键结论：`qwen3-vl-embedding` 的图文同空间能力，让「用宠物图片直接检索知识库」成为可行方案**——这对「拍照找相似病例/相似症状」这类功能是决定性的。若选 Qwen 作为 VLM，向量检索也建议选它，同一家、同一套凭证、同一张发票。

**成本可忽略**：10,000 条知识条目 × 300 Token = 300 万 Token × 0.7 元/百万 = **2.1 元**（一次性）。即使知识库做 10 倍也才 21 元。

**接口能力**（供 #63 决策）：ADR-0003 保留了向量检索但未定方案。**建议在 #63 里把「是否用 qwen3-vl-embedding 做图文同空间」作为一项显式决策**，不要默认只做文本向量——那会永久排除图片检索的可能。

### 给 #62（风险分级标准与评测集）

1. **「分诊准确率 ≥ 70%」在通用 VLM 上对皮肤场景是够不着的**：VetClaw 零样本纯图片 33–52%，加文本后 72–94%（4 分类 / 22 分类，样本量 443 / 1,736）。**准确率极度依赖任务定义与是否提供症状文本**——必须先冻结「几分类、给不给文本」再谈数字。
2. **评测集必须包含「JSON 字段合法性」维度**（见第 2 节）。
3. **评测集要按场景分层**（皮肤 / 耳道 / 排泄物 / 体态），不能用单一总体准确率掩盖差异——皮肤和排泄物的难度不在一个量级。
4. **细调窄模型是后期提升准确率的主要杠杆**：宠物皮肤方向已有 92.59%（50,000+ 张图，ResNet50+CBAM + BERT 融合）的公开结果，远高于通用 VLM 零样本。**建议 #62 把「是否需要专用皮肤分类模型」列为显式决策项。**
5. 离线评测可用 **Batch 半价**（qwen3-vl 全系），评测成本打对折。

## 10. 建议的决策与下一步

### 决策（可直接落到 #69 的路线里）

1. **VLM 主力：`qwen3-vl-plus`（快照 `2025-12-19`）承载风险分级；`qwen3-vl-flash` 承载常规问答与预筛。**
2. **VLM 备选：`GLM-4.6V` 做 A/B**，重点比「带图 tool call 的 JSON 稳定性」和真实延迟——这是两家差异最大的地方，也是我们最脆弱的地方。
3. **结构化输出：一律走 tool call + 客户端 schema 校验 + 一次修复重试**，不依赖 `json_object`。
4. **语音：`paraformer-v2` 录音文件识别**（0.00008 元/秒），实时识别留作后续可选项。
5. **向量（供 #63）：`qwen3-vl-embedding`**，图文同空间。
6. **不采用**：`qwen-vl-max`（老一代、无阶梯计价）、`GLM-4V-Flash` / `GLM-4.1V-Thinking-Flash`（4K/64K 上下文、≤1 图、不支持 base64，非生产可用）、`kimi-k3`（输出价 33 倍）、Hunyuan 视觉（贵 2–3 倍且宠物证据更少）。
7. **产品侧硬约束**：**图片是辅助模态，必须同时收集症状文本。** 纯图片分诊在公开实测中不可用。

### 下一步（开工前）
