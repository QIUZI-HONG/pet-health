# 不做线上收款，交易走到店付

平台不经手资金：订单只完成「预约 + 锁价 + 券抵扣计算」，实际付款在门店完成。

## Considered Options

- **微信支付 H5 / JSAPI**：平台先收款、再结算给商家，形成资金沉淀，可能构成二次清算（无证支付业务）。
- **微信支付服务商分账**：合规上最干净，但需要服务商资质或与持牌机构合作，接入复杂度最高。

选到店付的理由：资金二清合规、对账、退款、发票、结算周期这一整套成本，在当前阶段换不来对应收益——平台的价值在 AI 咨询与服务标准化，不在过一道资金通道。C 端做成 Web 后也没有 JSAPI 可用，这条路本身就更重了。

## Consequences

- 券的「线上抵扣」退化为纯展示，实际抵扣在门店完成。
- 商家后台的**结算中心**退化为对账视图：有流水与核销明细，没有余额与提现。
- 订单状态机里不需要「已退款」的资金流转，退款是线下的。
