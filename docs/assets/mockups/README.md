# 视觉稿归档

交付文档 4.16 节的 9 张原始 PNG，2026-09-27 从文档中的 COS 签名链接下载。

## 为什么要归档

那些链接**带签名，2026-12-26 过期**——过期后图全部失效。而文档 4.16 明确声明：

> 以下图片是开发完成的**目标视觉效果**……开发完成后截图对比，须做到**肉眼无差异**。
> 如果渲染图与《宠物AI健康管理平台完整方案》中的 ASCII 原型图在细节上有冲突，**以本节图片为准**——图片是最终视觉定义。

所以这批图是视觉验收的唯一基准，也是设计 token 的真实来源，不能只存在于会过期的链接上。

## 从这批图里取出的事实

`packages/ui/src/tokens.css` 的全部色值都从这 9 张图直接取像素得到。关键发现：

**交付文档 4.2 的「色彩规范」表与这批图是两套不同的配色。** 以品牌主色为例：

| | 4.2 表写的 | 视觉稿实际用的 |
| --- | --- | --- |
| 品牌主色 | `#2EAD6B` | **`#0EA382`**（五张主页面合计 29 万像素） |
| 主色浅底 | `#E7F7EF` | **`#E4F6F0`** |
| 页面背景 | `#F5F6F8` | **`#F5F7FA`** |
| 危险红 | `#F0483E` | **`#EF4444`** |
| 链接蓝 | `#4A9EF7` | **`#3B82F6`** |

`#2EAD6B` 在**任何一张视觉稿里都没有出现过**。按 4.2 表做出来的界面，无法通过文档自己那条「肉眼无差异」的验收。**以图为准。**

## 命名

文件名与交付文档里的原图名一一对应，**只有一处例外**：`07_服务者后台.png`
（文档里叫「07_商家后台」）。改名的理由是本仓库的命名纪律——`CONTEXT.md` 把
「商家后台 / 商家 PC 后台」列为 _Avoid_ 词，统一说**服务者后台**；留一个违反术语的
文件名，等于让每个后来者都要先怀疑一次「这是不是另一个东西」。
跨文档检索时按「07_」这个编号对上原文即可。
