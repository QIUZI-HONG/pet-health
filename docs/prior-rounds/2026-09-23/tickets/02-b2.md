## Parent

#25（地图：C 端（Web + H5）——用户自助侧可演示产品）

## What to build

C 端自助的宠物与健康档案能力，**全部限定「自己的宠物」**：

- `/app/pets` CRUD：自助建档（名称 / 物种 / 品种 / 年龄 / 体重 / 头像 / 慢性病标签 / 防疫四日期）、编辑；他人宠物 403。
- 健康记录：今日打卡（5 项，可选填，同日重复则合并——复用一期语义）、按日期范围查询、修改当日记录（改后重算当日评分与连续天数）。
- 健康档案聚合：基础信息 + 记录时间轴 + 健康评分与 6 分项 + 连续打卡天数（复用一期 `health-profile` 的聚合逻辑，换数据范围）。
- **复用一期的健康评分算法**（规则式、带 `algorithm_version`）——不要另写一套。

## Acceptance criteria

- [ ] 用户 A 拿不到也改不了用户 B 的宠物与记录（403）
- [ ] 打卡同日两次合并为一条；连续天数与评分按一期规则重算
- [ ] 档案聚合一次请求返回基础信息、时间轴、评分 6 分项、连续天数
- [ ] 新宠物历史记录 < 3 条时体重偏离项不参与计分（一期已定规则，回归覆盖）
- [ ] API 测试（HTTP + 真库）覆盖以上
