## What to build

一份**验收用的需求对照表**（新建 `docs/design/requirement-traceability.md`）：把交付文档八卷里可对照的条目逐条列出，每条标三态之一：

- **已实现**（对应哪个模块 / 页面 / 测试）
- **有差异**（差异内容 + 理由 + 出处文档或 ADR）
- **出局**（原因 + 出处，如 ADR-0013 的演示档取舍）

覆盖范围：第一卷功能清单（模块 A–D）、第二卷页面结构、第三卷 UI 规范、第四卷技术选型、第五卷表结构、第六卷接口、第七卷排期、第八卷测试方案与上线检查清单。**每条都要能落到具体出处**，不许写「基本实现」。

## Acceptance criteria

- [ ] 八卷逐卷有对照小节，条目可核对
- [ ] 三态齐全，差异与出局都有出处
- [ ] 与 `api-contract.md` 的差异表、`feature-inventory.md` 不矛盾（矛盾处回头修）
- [ ] `README.md` 指向它
