# 设计 token 以视觉稿取色为准，交付文档 4.2 的色彩规范表失效

交付文档内部自相矛盾：4.2 节「色彩规范」表给出一套色值（品牌主色 `#2EAD6B`），4.16 节的视觉稿用的是另一套（品牌主色 `#0EA382`）。文档 4.16 声明「以本节图片为最终视觉定义」，因此以图为准。

## 证据

直接解码 `docs/assets/mockups/` 里的 9 张 PNG 统计像素频次：`#0EA382` 在五张主页面截图中共出现 29 万像素，是唯一的品牌主色；**`#2EAD6B` 在任何一张图里都没有出现过**。整套 4.2 表——背景、语义色、链接色、文本色——都与图不符，只有橙色 `#FF8A3D` 一条对得上。

## Consequences

- `packages/ui/src/tokens.css` 的每个色值都标注了 `[取色]`（从图中取到）或 `[派生]`（图中不存在的状态，如按下态）。
- 按 4.2 表实现会通不过文档自己那条验收条款（「开发完成后截图对比，须做到肉眼无差异」）。
- 代价不对称：如果日后对方澄清应以 4.2 为准，那意味着**视觉稿本身要重做**，而不只是改几个变量。这条决策的可逆性因此是假的——先照图做，风险更低。
