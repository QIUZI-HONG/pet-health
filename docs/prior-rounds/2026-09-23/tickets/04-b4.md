## What to build

两条线的后端：C 端消息中心，与服务浏览/预约。

- **消息流**：合并「我的宠物的健康预警」与「我的预约状态流转」按时间倒序分页；未读数按契约票口径（推荐 `app_user.messages_seen_at` 单列）；提供标记已看。
- **服务浏览**：仅 `APPROVED` 且未停用的服务者列表/详情（类型、简介、服务项）；服务项与未来 14 天号源（按日期查余量）。
- **预约**：`POST /app/appointments`（自己的宠物 + 选定号源；同步建订单、无支付；地址默认取 `app_user.address`、可覆盖）、我的预约列表/详情（时间倒序）、取消（必填理由；沿用一期状态机与号源释放）。
- 预约规则沿用一期：14 天窗口、只校时间冲突（允许同宠物重复约）、已过时段不可约。
- 状态流转日志对 C 端可见（我的预约详情里显示状态与时间）。

## Acceptance criteria

- [ ] 号源占用走一期条件更新防超卖（并发测试覆盖）
- [ ] 满号 / 已关闭号源建单返回业务错误（不 500）
- [ ] 只能用自己的宠物建单；他人宠物 403
- [ ] 取消后号源释放、订单置 `CANCELLED`（与一期语义一致）
- [ ] 消息流按时间倒序合并两类来源；未读数随查看归零
- [ ] 服务者列表不含未审核 / 已停用者
- [ ] API 测试覆盖以上
