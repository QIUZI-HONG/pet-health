# 档案分项：字段清单、分项与维度的映射、多源写入与时间轴

回答地图 [#90](https://github.com/QIUZI-HONG/pet-health/issues/90)，并作为切片 [#102](https://github.com/QIUZI-HONG/pet-health/issues/102) 的依据。
[ADR-0023](0023-archive-section-single-table.md) 已经定了「**一张 `archive_record` + `structured_payload` 承载 8 个分项**」这个容器层面的决定；这一票把里面**装什么**定下来——8 个分项各自记什么、多源写入以谁为准、哪些事件进时间轴、照片视频与文件模块怎么分工。

交付文档 F004 只给了 8 个分项的**名字**（4.16.4 的 8 个模块入口、4.17 的「核心指标 / 证件与合规 / 行为档案 / 情绪档案 / 卫生档案 / 饮食档案 / 老年专项 / 照片·视频 / 就医记录」），**每一项具体记什么、哪些必填，文档完全没定义**。所以下面每一条都是补的，不是抄的。

> **本轮由项目所有者拍板的三条**（与本文其余推断不同，它们不是工程推出来的）：
> ① 分项是**原始记录**、五维评分是**派生视图**，不为分项另建一套评分口径；
> ② 多源写入**按来源分级**、冲突保留两条、**不做静默覆盖**（决定三）；
> ③ 时间轴**只收四类事件**——就医记录、疫苗/驱虫、**异常**打卡、服务者报工；**正常打卡不进时间轴**（决定四）。

## 决定

### 一、8 个分项 = 一张表上的 9 个 `category`

分项是**界面的录入与展示单元**（CONTEXT.md：「分项」是录进去的），`category` 是**落库的编码**。两者的映射固定成下表，代码里唯一的权威是 `ArchiveSection`（`com.pethealth.record.domain`）：

| 分项（sections） | 码 `section` | 落库 `category` | 记什么 | 必填 |
| --- | --- | --- | --- | --- |
| 核心指标 | `metrics` | 1 体重、3 排泄 + **10 其他指标** | 体重、排泄，外加体温 / 心率 / 呼吸 / 饮水这类「一个名字 + 一个数值 + 一个单位」的指标 | 标题 + 取值 |
| 饮食 | `diet` | 2 | 打卡里的饮食项 | 标题 |
| 行为 | `behavior` | 4 | 打卡里的行为项 | 标题 |
| 情绪 | `mood` | 5 | 打卡里的情绪项 | 标题 |
| 卫生 | `hygiene` | 6 | 打卡里的卫生项 | 标题 |
| 证件与合规 | `documents` | **7 防疫** + **11 证件** | 疫苗/驱虫（已有独立录入接口）与证件：免疫证、犬证/猫证、检疫证明等，含**有效期** | 标题 + 证件用 `due_on` |
| 老年专项 | `elderly` | **12 老年专项** | 复查、用药、慢病观察三类记录（专项照护开启后才有意义，见 [ADR-0032](0032-care-mode.md)） | 标题 |
| 照片视频 | `media` | **不落这张表** | **派生自分片 #95 的 `file_object`**，取 `biz_type=profile` 的档案照片；打卡/防疫照片（`checkin` / `epidemic`）在各自记录里看；**服务者留痕照片（`care`，三道照片墙 #107）不得混进用户的档案照片墙** | — |
| （时间轴的来源）就医记录 | `medical` | 8 | 一次就诊：机构、事由、结论（用户自述，**平台不产出医疗记录**——CONTEXT.md 的「健康档案」条） | 标题 + 日期 |

**为什么就医不是第 9 个分项**：交付文档 F004 把「就医记录」与 8 个模块并列写，但它在 4.16.4 的界面里是**时间轴的展示形态**，不是录入单元。这里按「就医 = 时间轴的来源之一，不是一个入口」处理——`category=8` 仍然可录（时间轴详情里给入口），但它不出现在 8 个分项的入口列表里。

**为什么照片视频没有 `category`**：照片的消息面在文件模块（签名读地址、缩略图、体积与魔数校验都已经在那里）。把 URL 抄进 `archive_record` 就多一份要跟着删的副本（ADR-0023 第二条），所以「照片视频」分项的读接口**直接列 `file_object`**。

**两条形状约定**：

- 结构化载荷写 `structured_payload`（`JSON`，V15 新增列）。打卡与防疫**继续用** `content`（VARCHAR(1024) 的扁平键值，ADR-0018/0019 的既有写路径），读接口把两者**归一成同一个 `payload` 视图**再下发。留着 `content` 不是舍不得删：改它要动打卡、防疫、评分、提醒四处的写路径与它们的测试（其中打卡的原子 upsert 直接依赖那一列），而收益只是少一列。
- 新分项的取值**同时写一份进 `structured_payload.value` 与 `numeric_value` 列吗？不。** `numeric_value` 保持「体重专用」（评分与趋势提醒都按它算），其它指标的数值留在 JSON 里——一个数值两种精度来源，迟早对不上。

### 二、分项与评分维度的映射（两套结构不同构）

CONTEXT.md 已经把这两套词分开了（分项是录进去的、维度是算出来的）。映射关系是 **多对多**，落在 `HealthScoreService` 的分组表里，这一票不改它，只把口径写清楚：

| 评分维度 | 覆盖的分项 / `category` |
| --- | --- |
| 生理 | 核心指标（1 体重、3 排泄）、饮食（2） |
| 行为 | 行为（4）、情绪（5）——**情绪没有独立维度**，并入行为 |
| 卫生 | 卫生（6） |
| 防疫 | 证件与合规里的防疫部分（7），取值按 `due_on` 的到期状态（[ADR-0025](0025-scoring-kb-seed-budget-compliance-routing.md)） |
| 老年 | 同「生理」的来源，**仅专项照护开启时计入**（[ADR-0032](0032-care-mode.md)） |

**`category=10/11/12`（其他指标、证件、老年专项）不参与任何维度**：它们不是「每天有没有记」意义上的持续观察项，纳入完整度公式只会让用户可以靠补录证件把分数刷上去。这一条是刻意的——ADR-0018 的公式量的是「你观察得勤不勤」，不是「你材料齐不齐」。

### 三、多源写入：**按来源分级 + 冲突两条都留**（本轮拍板）

F004 要求「手动 + AI + 商家报工三源」。`archive_record.source`（1 用户 / 2 AI / 3 服务者报工）已有（ADR-0023 第三条），本票补上的规则是：

| 分项 | 权威来源（`authoritative`） | 理由 |
| --- | --- | --- |
| 证件与合规（11）、防疫（7） | **服务者报工（3）** | 证件与接种是被机构核验过的事实，服务者现场录入比用户回忆准 |
| 体重 / 饮食 / 排泄 / 行为 / 情绪 / 卫生（1–6）、其他指标（10）、老年专项（12）、就医（8） | **用户（1）** | 这些是主人在家的观察，机构看不到 |
| —— | **AI（2）永远不是权威来源** | AI 只产生建议；它写进来的行可读、可查，但不作为该分项的「当前值」 |

四条落地口径：

1. **「以谁为准」= 读时的权威标注，不是写时的覆盖。** 读接口对每条记录给出 `authoritative`（按上表算），前端把权威那条作为分项的「当前值」，其余按时间列出。**权威来源缺席时，次一级来源自然成为权威**（例如没有报工记录的证件，用户自己录的那条就是权威）——否则「以报工为准」会变成「没报工就没内容」。
2. **冲突时两条都保留**：任何来源都不删改别人的行，时间轴上两条都在（标注来源与时间）。**不做静默覆盖**——静默覆盖是「用户明明记过，打开却不见了」这类投诉的源头。
3. **打卡六项仍是「一天一项一条、重复提交即更新」**（ADR-0018）——那是**同一来源**的修改语义；跨来源的并存由第 1、2 条管。
4. 服务者报工写档案的路径属切片 [#107](https://github.com/QIUZI-HONG/pet-health/issues/107)，本票只保证「它写进来的行**能读、能进时间轴、能进报告**」——`source=3` 的分支已实现并有测试，不依赖 #107 是否落地。

### 四、时间轴：**只收四类事件**（本轮拍板）

ADR-0023 第一条已经定了「时间轴 = `archive_record` 按 `record_date` 排序」，本票把**哪些事件进**定下来（这是拍的板，不是推断）：

| 事件类型 | 取数条件 |
| --- | --- |
| 就医记录 | `category = 8` |
| 疫苗 / 驱虫 | `category = 7` |
| **异常打卡** | `category` 1–6 且 `abnormal = 1` |
| 服务者报工 | `source = 3`（任意 category，含将来的报工行） |

**正常打卡不进时间轴**：六项日常记录一天最多 6 条，一周 42 条，时间轴会被淹没成一个流水账——它失去的正是「回头找那次就医/那次异常」的检索价值。正常打卡在打卡卡、评分趋势与分项列表里看，那里本来就是它的位置。
**分项记录（10 其他指标 / 11 证件 / 12 老年专项）也不进时间轴**（同上，四类之外）：它们在各自分项里按期列出，分项详情就是它们的「时间轴」。
**报告不进**：报告是**派生视图**（ADR-0031），把它塞进时间轴会让「时间轴 = 事实」变成「时间轴 = 事实 + 我们对事实的解释」。

时间轴倒序、分页（每页 20，上限 100），可按 `type` 与日期区间过滤——docs/conventions.md 的默认排序。

### 五、导出补分项

`/users/me/export` 原先只导出打卡与防疫（`content`）。本票把 `structured_payload` 与 `source`、`due_on` 一起带进导出（`AccountExportView.pets[].records[]`），**不新增第二个导出接口**：一个「导出我的数据」按钮给出两份格式相近的副本，是合规友好的反面。

**报告不进导出**（ADR-0031 决定六）：导出给的是「医院能看的原始档案」，报告是平台对数据的解释。

## Considered Options

**每个分项建独立子表**：字段强约束，但 ADR-0023 已经否决过（时间轴会变成跨表 union）。
**把 8 个分项的差异字段分别建成 8 个视图 + 8 组接口**：接口面×8，前端×8，而差异其实只有「标题/取值/单位/到期日/备注」五个字段。
**前端直接读写 `structured_payload` 的自由 JSON**：最灵活，但契约就退化成 `object`，前端类型检查失效（AGENTS.md：前端不手写接口类型，靠契约生成）。
**分项记录也写 `numeric_value`**：见决定一的最后一条。

## Consequences

**分项记录的字段是弱的**——`structured_payload` 的结构由**代码**守（`ArchiveSectionService` 按分项校验必填与长度），不由数据库守。这是 ADR-0023 已经认下的代价，本票只是把它落到具体字段上：换分项字段时改一处常量表 + 契约，不需要迁移。

**「证件与合规」与「防疫」共用一部分数据**：分项读接口里 `documents` 会同时列出 category 7 与 11。这样做的好处是用户看到的「证件与合规」是完整的（免疫证与疫苗记录本来就该在一起），代价是**这一分项的条数不等于某个单一 category 的条数**——按 `category` 做统计时要注意（报告里用的是分开的计数）。

**未做**：视频（ADR-0004 已排除）；「分享给医院」的加密链接（交付文档 4.16.4 的底部按钮）依赖服务者侧的授权访问（#72 的服务者查档案），本票只做导出。

## 待澄清

1. **证件类要不要「有效期 + 到期提醒」**：证件与合规已把有效期落在 `due_on` 列上（`ArchiveRecordRequest.due_on`），但**到期提醒还没接**——疫苗/驱虫的到期提醒走 `reminder_rule.type=1/2`，证件没有对应的提醒类型。要不要加、与 [#78](https://github.com/QIUZI-HONG/pet-health/issues/78) 的资质到期策略是否合并成一套「到期提醒」，需要甲方定（本轮拍板只到「记录有效期」这一层）。
2. **证件与合规要不要审核**：交付文档只说「证件」，没说平台是否核验（服务者资质有审核链路 #104，用户侧的证件没有）。本票按「用户自述 + 照片留档、平台不核验」实现，**对外文案不得暗示已核验**。
3. **就医记录的字段深度**：用户自述「机构/事由/结论」，平台不算医疗记录。若要支持上传病历单照片并 OCR 提取诊断，属新能力（还要过 #74 合规），需要甲方确认边界。
4. **分项记录是否要进时间轴**：本轮拍板的时间轴只收四类事件，因此其他指标 / 证件 / 老年专项的记录**只在各自分项里列出**。若产品希望「复查记录也出现在时间轴上」，那是对第四条口径的修订，改一处过滤条件即可，先问清意图。
5. **时间轴是否要收录 AI 咨询事件**：AI 咨询留痕在 `ai_consult`（另一模块），本票的时间轴只收档案侧事实。若要「AI 问诊也进时间轴」，需要 ph-ai 暴露只读接口——先问清产品意图，别顺手 join（ADR-0006）。
