# 范围与口径（第三批）：社区分期、F011 规则版、检索状态语义、考核缺项

## 一、社区（F020）先做经验卡片 + 问答互助，慢病社群后置

- **本期**：经验卡片（用户录入打卡/就医后可一键生成**匿名**卡片）+ 问答互助（提问 / 回答 / 采纳）。嵌入位置与发文权限按 [ADR-0041](0041-community-security-test-perf.md) §一（不做独立 Tab、权益码 `community.post`、内容进审核）。
- **后置**：慢病社群。它需要按慢病标签聚合的内容流与**内容种子**，两样现在都没有——先做就是一个没人发帖的空壳，**而空壳比没有更伤**（用户点进去一次就再也不点了）。
- 后置不是遗忘：慢病标签体系已经存在（档案侧的慢病字段），等有真实慢病用户与内容再生产时补上。

## 二、F011「AI 帮我找服务」先做规则版

- 用**已入库的症状分诊知识** + 目录项（[ADR-0034](0034-service-catalog-and-pricing.md) 的两级目录）的关键词/分类映射做推荐，**不调模型**。
- 理由：交付文档 F011 的诉求是「描述症状 → 推荐项目」，规则版立刻可用，而且**推荐理由说得出来**（「因为你说腹泻，推荐肠胃诊疗」）——模型版在现在还没有 vetted 知识条目的情况下，只会给出一段编出来的理由。
- 模型意图路由（[ADR-0025](0025-scoring-kb-seed-budget-compliance-routing.md) 第五节）等检索层接上后**叠加**，不是替换。

## 三、`retrieval_check` 的修法：区分「故障」与「人为关闭」

- 让 ops 配置加载**暴露「是否读成功」**，据此把「开关读不到」报成 `unavailable`（故障），只有开关**确实为关**时才报 `disabled`。
- fail-closed 的行为**保留**（配置不可用时不启用检索），改的只是**上报给调用方的语义**。
- 理由：这个字段存在的全部意义就是让运维区分两件事——报成 `disabled` 意味着知识库挂了却没人告警，而「知识库挂了」正是 AI 回答退化成无来源建议的原因。

## 四、考核缺项：区分「未履行」与「无该维度要求」

- **该做而没做**（例如平台有必出券目录、服务者一张没出）→ 记 **0 分**。
- **平台侧无该维度要求**（例如该品类根本没有券可出）→ 该维度**不参与并重算权重**，且分数明细里注明「未参与」。
- 修订 [ADR-0039](0039-invite-review-assessment-analytics.md) §三 的考核算法说明。
- 理由：把两者混为一谈，要么冤枉新服务者（平台没给条件却记 0），要么把未履行洗白（该出券而没出也算「未参与」）——而出券是平台的核心机制，不能被洗白。

## 附：报工时间戳由服务端给

交易域契约待澄清里的最后一条（平均服务时长要用报工时间戳）：**取服务端落库时刻**（`AppTime.now()`），**不接受客户端传入**。理由：客户端时钟不可信，而考核与平均时长都拿它当依据。
