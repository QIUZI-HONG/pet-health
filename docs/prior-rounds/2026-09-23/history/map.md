## Destination

一个能跑、能演示的 **C 端（Web + H5，一套响应式前端）**：用户用手机号自助注册登录，自建宠物与健康档案、每日打卡、看健康评分与预警，与 AI 管家对话得到风险分级与建议，浏览服务者与服务项并提交预约（不接支付）。后端新增 `/api/v1/app/**` 模块（自有鉴权与数据范围），前端独立容器部署到云主机新端口，手机浏览器与微信内可打开演示。走完时，一期那 13 张实现票与 #7/#9/#10 三张决策票同步结案。

## Notes

### 上游背景

- 这是**同一个实习 MVP 项目**的第三轮：① 一期规划（地图 #2）→ spec #11 → 实现票 #12–#24（代码已实现并验证，见 `README.md`）；② 部署手册 / 手册截图 / 采购与合规清单（9/23）。公司交付文档（PRD / 原型 / UI / 架构 / DB / API / 排期 / 测试 八卷）仍是**验收基准**，与它的差异必须记录（沿用一期做法：api-contract.md 的差异表）。
- 一期把 C 端明确列为 Out of scope（ADR-0001：C 端二期）。本轮**把 C 端提前**：微信小程序对个人主体不可行（9/23 已核实，见 `docs/design/procurement-and-compliance.md`），故 C 端形态改为 **Web + H5**。ADR-0001 要补修订记录（见收尾票）。

### 已确认的决策（charting 时，2026-09-23）

1. 目的地是**可运行的产品**（不是计划）。本图**携带执行**——tickets 是「要做的事」，不是纯决策票。
2. **范围 = 健康线 + 服务预约线**：打卡记录 → 档案/评分 → AI 问答 → 健康预警与预约状态消息 → 浏览服务者/号源 → 提交预约（不接支付）。社区、商城、宠物用品、评价、权益裂变、支付、转人工一律不做。
3. **一套响应式前端**（移动优先，桌面自适应），一个代码库、一个部署。
4. **C 端账号**：`app_user` 加凭证（手机号 + 密码），**自助注册**（`source=SELF`）；无短信通道，不用验证码。
5. **AI 问答 = 聊天式界面 + 后端单轮分析**（沿用一期「不引入会话概念」）；**每日 3 次配额**，只计 `source=SELF` 的咨询（代录不占用户额度），超限 429 + 文案「今日 3 次已用完，明天再来」（无升级/邀请路径）。
6. **消息中心 = 健康预警 + 预约状态变化**（派生流；不做交付文档 §1.4.3 的天气/疫情等 8 类提醒）。未读计数拟用 `app_user` 加一列 `messages_seen_at` 支撑，**不新建消息表**（契约票冻结具体形状）。
7. **后端接口**：新建 `/api/v1/app/**` 模块（复用服务层；与一期 `ProviderSelfController` vs `ProviderAdminController` 同构），全部需登录，**不开放匿名浏览**。
8. **部署**：C 端**独立容器 + 新端口**（如 8081），后台 80 端口与已验证形态不动；今天一并上云，并在手机浏览器与微信内各验一遍（微信内不做 OAuth / JS-SDK）。
9. **信息架构**：底部 **4 Tab**（首页 / 档案 / AI 管家 / 我的），对齐交付文档（去掉社区）。二级页：注册登录、宠物建档/编辑、打卡录入、消息中心、AI 对话与记录、服务者列表/详情、选服务项与号源、预约确认、我的预约与取消。
10. **AI 回答每条带合规标识**：「本回答由 AI 生成，仅供参考，不构成诊断；如症状紧急请立即就医」；红色等级置顶「就医准备清单」。
11. **演示数据**：种子演示账号（手机号+密码，2 只宠物 + 数十天记录 + 评分 + 若干预警）与现场注册闭环**两者都备**（也是旧票 #7 的收尾）。
12. 一期遗留**本轮顺带收尾**：T1–T13 补结案关闭；#7 / #9 / #10 结案。
13. **技术栈**：Vue 3 + **Vant 4**（移动组件库）+ Vite；色彩与字号沿用交付文档第三卷（主色 `#4CAF7D`、辅色 `#FF8A5C`、危险 `#FF6B6B`…）。

### 按默认生效（用户未反对，如要改请提）

- C 端不做「我的订单」独立页——订单信息并入预约详情（佣金规则不对用户展示）。
- AI 对话历史放在 AI 管家页内，不进消息中心。
- 上门类服务地址：默认取 `app_user.address`，下单页可覆盖（`appointment.service_address`）。
- 预约规则完全沿用一期：14 天窗口、只校时间冲突、取消必填理由、不扣费。
- 后台界面本期不动（若列表需要按 `source=SELF` 筛选，只做小改）。
- 不做深色模式、不做多语言。

### 纪律与素材

- **契约先行**：先冻结 `docs/design/api-contract.md` 的 C 端章节，前后端各会话都按它写。
- **四套验证要扩到 C 端**（README 的「改完挨个跑」）：后端测试 / 端到端冒烟 / UI 联调（真渲染断言）/ 前端构建。
- 数据范围**服务端强制**；越权 403；金额是字符串；枚举大写；时间带时区。
- 术语一律用 `CONTEXT.md`（C 端带来的新词由收尾票补）。
- UI 规范直接沿用交付文档第三卷，移动组件映射到 Vant。

### 环境（本机坑）

- `gh` 走 `~/.local/bin/gh`（Bash 工具里必须写全路径）；`--body-file` 要 Windows 形式路径。
- Docker 走 `~/.local/bin/docker` wrapper；挂 WSL 路径用 UNC 形式；npm 依赖装 Linux 版（容器内跑 dev/build），registry 用 npmmirror。
- 部署手册 `docs/design/deploy-runbook.md`；远端自检 `scripts/remote-selfcheck.sh`。

## Out of scope

- **微信小程序 / APP 客户端** —— 个人主体不可行（9/23 核实）；C 端形态已定为 Web + H5。
- **真实支付通道、在线兽医转人工付费、订阅/优惠券/邀请裂变**（模块 D）—— 无企业主体、无支付载具。
- **社区、商城、宠物用品推荐、服务评价与商家排名** —— 依赖内容与评价人。
- **微信登录 OAuth、微信 JS-SDK（分享卡片/公众号）、微信订阅消息推送** —— 均需认证主体。
- **短信验证码** —— 无通道（一期已定）。
- **地图 / 定位 / 距离排序、附近医院推荐**。
- **8 类主动提醒**（天气/疫情/趋势等）与提醒设置页 —— 需外部数据源；消息中心只收预警与预约状态。
- 多语言、深色模式、离线能力。
- 服务者端 / 运营端的功能扩展 —— 本期只做 C 端，后台保持现状（除来源筛选小改）。
