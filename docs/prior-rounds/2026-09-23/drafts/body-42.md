## What to build

合规里「可删除、可注销、最小必要」的落地（ADR-0012 / ADR-0013）：

- **注销**：`POST /app/auth/close-account`（路径由契约票冻结）；注销后不能登录、token 版本递增立即失效；个人信息按留存策略处理——健康数据删除、手机号脱敏（保留不可逆摘要用于防重复注册）、必要留痕保留。
- **手机号脱敏**：接口返回与后台展示一律 `138****0001`；只有服务端内部按需取全量。
- **最小限流**：注册与登录按 IP 限流（同 IP 每小时若干次，超限 429），防脚本刷号；沿用一期登录失败锁定的实现风格。
- **留存清理任务**：定时任务（与 `SCHEDULE_*` 同构）删除或匿名化超过 12 个月的 AI 咨询记录；执行失败要打点（否则「到期删除」会静默失效）。

## Acceptance criteria

- [ ] 注销后：不能登录、旧 token 立即 401、健康数据删除、手机号已脱敏
- [ ] 脱敏在 C 端接口与后台用户页一致
- [ ] 限流生效（脚本连打触发 429），正常用户不受影响
- [ ] 清理任务可手动触发验证，失败打点
- [ ] API 测试覆盖注销与限流
