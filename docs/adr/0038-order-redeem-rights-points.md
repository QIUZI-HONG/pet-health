# 第五批裁决：订单状态机、核销凭证、权益引擎、积分与任务

四条都是交易与增长链路上「开工前必须定的口径」，互不依赖，故合并（同 [ADR-0024](0024-quota-care-community-tracking-packages.md) 的处理）。它们全都建立在 [ADR-0036](0036-money-semantics-offline.md)（钱在门店付）之上。

## 一、订单状态机（挡 [#77](https://github.com/QIUZI-HONG/pet-health/issues/77) → #109）

**四态 + 双侧取消。** 交付文档的六态里 `待支付 / 已支付 / 已退款` 在到店付下失去语义，**不定义**（状态码从 0 重新排）：

| 码 | 状态 | 进入条件 | 谁能推进 |
| :-: | --- | --- | --- |
| 0 | 待接单 | 用户下单成功（同时占用号源） | — |
| 1 | 已预约 | 服务者接单 | 服务者 / 运营 |
| 2 | 履约中 | 到店核销 | 服务者 / 技师 |
| 3 | 已完成 | 报工提交完成 | 服务者 / 技师 |
| 4 | 已取消 | 见下 | 用户 / 服务者 / 运营 |

- **取消规则按阶段分**：`待接单` 用户可自由取消；`已预约` 用户发起取消需服务者同意（拒绝要填理由）；`履约中` 不可取消（只能走完成，或由运营干预）。
- **没有「30 分钟未支付自动取消」**：没有支付就没有这个待办。改为**超时提醒**——预约时间过后仍未核销 → 提醒服务者处理；超 24 小时 → 标记异常进看板，**不自动取消**（自动取消会让用户白跑一趟店）。
- **非法迁移一律返回冲突码（40900）**，不是参数错误：这是状态冲突，不是参数写错。
- **并发抢同一时段**：号源按时段容量占用（[CONTEXT.md](../../CONTEXT.md) 的号源条目），用唯一键/乐观锁实现，后到者得到 40900「该时段已被预约」——交付文档 2.4 要求的正是这条。
- **没有退款单**：清退服务者时未完成订单转 `已取消`（ADR-0036）。
- **与券的交接**：下单锁定券（占用）→ 取消释放 → 核销时券转「已用」（[#53](https://github.com/QIUZI-HONG/pet-health/issues/53) 的三层对象）。

## 二、核销凭证（挡 [#55](https://github.com/QIUZI-HONG/pet-health/issues/55) → #109）

**6 位核销码 + 手工输入**，不使用二维码（桌面浏览器没有摄像头，两端都在电脑上）：

- C 端订单详情展示 6 位核销码，**到预约时间才可见**（太早泄漏等于把凭证挂在外面）。
- 服务者后台：输入核销码，或按**手机号 / 订单号**搜索定位订单后核销。不要求扫码枪等硬件。
- **幂等与冲突**：核销是**原子的条件更新**（并发双击只有一个成功）；订单重复核销 → 40900；券的重复核销 → **80002**（`COUPON_REDEEMED`，本 ADR 给了它第一个真实产出路径）；券不满足门槛或范围 → **80001**（`COUPON_UNAVAILABLE`）。
- **核销 ≠ 收款**：界面必须写明「费用在门店直接付给服务者」（ADR-0036）。

## 三、权益引擎（挡 [#80](https://github.com/QIUZI-HONG/pet-health/issues/80) → #112）

**权益码表 + 实时判定 + 来源优先**：

- **权益码**（初始一组，运营可扩）：`ai.unlimited`（无限 AI 问答）、`report.full`（完整报告）、`community.post`（社区发帖）、`quota.ai.bonus`（额外咨询额度）。
- **每条来源各写一条授予**（码 + 来源 + 到期）：邀请（永久）、打卡阶梯（当月）、订阅（若将来有载体）。
- **「取最高」= 取来源优先级最高的那条**：订阅 > 邀请（永久）> 打卡（当月）。**不按到期时间比较**——「邀请得永久 + 订阅得月度」这种组合下，取最晚到期会把语义算错。
- **到期只回收该来源授予的那一条**：订阅到期不触碰邀请得的永久权益。
- 对外一个查询：`rights(userId) → {码: {是否生效, 来源, 到期}}`，各模块据此判定，不各自查表拼规则。
- **`care.mode` 不作为权益码**：交付文档把「专项照护模式」列为权益之一，但 [ADR-0032](0032-care-mode.md) 已定它按医学事实（7 岁 / 慢病）**自动开启**。两处不能同时成立——否则会出现「够条件但权益不足、于是看不到专项入口」的自相矛盾。**专项照护归「照护事实」，权益码只表达可授予的能力**。

## 四、积分与任务（挡 [#73](https://github.com/QIUZI-HONG/pet-health/issues/73) → #113）

**行为发分、只兑平台补贴券**：

| 行为 | 分值 | 频次约束 |
| --- | :-: | --- |
| 每日签到 | 1 | 每日 1 次 |
| 打卡 | 3 | 每日 1 次（按业务日） |
| 邀请有效注册 | 20 | 每有效邀请 1 次（被邀请人完成建档才算有效） |
| 评价晒单 | 5 | 每单 1 次，每月上限 5 次 |
| 完善档案 | 10 | 一次性 |

- **每日获取上限 20 分**（邀请与一次性项不占该上限，否则大额奖励会被日上限吃掉）。
- **兑换只兑券**（交付文档 F017），且兑的是**平台补贴券**——成本归平台，**不消耗服务者的贡献额度**（否则等于把兑换成本转嫁给服务者，直接抵消它的出券意愿）。
- **任务中心**：每日任务（签到 / 打卡 / 查看 AI 建议 / 分享）与每周任务（完成 5 次打卡 / 邀请 1 人）两档，清单入库存配置。
- **月度阶梯（F018/P1）**：先落「月度累计 → 阶梯发券」的定时任务骨架；**年度大奖留白**（没有规则依据，不编）。
- **与权益的边界（票里点名要钉死）**：权益与积分是两套账——同一行为**可以同时**推进权益阶梯计数与积分发分，但**奖励物不得重复**（打卡给积分，就不再用同一行为发一次券；阶梯券只在达到门槛时发一次）。
- **反刷**：签到、邀请、兑换的反作弊与 [#54](https://github.com/QIUZI-HONG/pet-health/issues/54)、[#121](https://github.com/QIUZI-HONG/pet-health/issues/121) 合流。

## Consequences

- 交付文档 F014 的六态收敛为四态 + 取消；`order` 表的 `status` 注释要一起改（迁移里改注释即可，不改列）。
- `ErrorCode` 里预留的 80001 / 80002 现在有了真实产出路径（券不可用 / 券已核销），90001 归定价区间（[ADR-0034](0034-service-catalog-and-pricing.md)）。
- 权益引擎的「订阅」来源**预留但无载体**：ADR-0036 之后订阅只能线下签约 + 后台标记，属 [#71](https://github.com/QIUZI-HONG/pet-health/issues/71)。
- 核销码是「可读出的 6 位数字」，**不是安全凭证**（不防截图、不防转发）——它的风险由「谁有权核销 + 核销幂等 + 核销需要服务者在场」兜住，不是靠码本身。
