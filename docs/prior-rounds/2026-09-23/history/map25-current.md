## Destination

一个能跑、能演示的 **C 端（Web + H5，一套响应式前端）**：用户用手机号自助注册登录，自建宠物与健康档案、每日打卡、看健康评分与预警，与 AI 管家对话得到风险分级与建议，浏览服务者与服务项并提交预约（不接支付）。后端新增 `/api/v1/app/**` 模块（自有鉴权与数据范围），端到端跑通并部署到可演示的环境；交付物（手册、需求对照表、提交包）齐备。走完时，一期那 13 张实现票与 #7/#9/#10 三张决策票同步结案。

- 一期把 C 端列为 Out of scope（ADR-0001）。本轮**把 C 端提前**并改为 **Web + H5**（小程序对个人主体不可行，9/23 核实）。ADR-0001 已补修订记录；新增 ADR-0011（接入与账号）/ 0012（观测与留存）/ 0013（演示档取舍）。

### 已确认的决策（charting 时，2026-09-23）

1. 目的地是**可运行的产品**（不是计划）。本图**携带执行**——tickets 是「要做的事」，不是纯决策票。
2. **范围 = 健康线 + 服务预约线**：打卡记录 → 档案/评分 → AI 问答 → 健康预警与预约状态消息 → 浏览服务者/号源 → 提交预约（不接支付）。社区、商城、宠物用品、评价、权益裂变、支付、转人工一律不做。
3. **一套响应式前端**（移动优先，桌面自适应），一个代码库、一个部署。
4. **C 端账号**：`app_user` 加凭证（手机号 + 密码），**自助注册**（`source=SELF`）；无短信通道，不用验证码。
5. **AI 问答 = 聊天式界面 + 后端单轮分析**；**每日 3 次配额**，只计 `source=SELF`（代录不占额度），超限 429 + 文案「今日 3 次已用完，明天再来」。
6. **消息中心 = 健康预警 + 预约状态变化**（派生流；不做 8 类主动提醒）。未读计数用 `app_user` 加一列支撑，**不新建消息表**。
7. **后端接口**：新建 `/api/v1/app/**` 模块（复用服务层），全部需登录，不开放匿名浏览。
8. ~~部署：今天上云~~ → **已改**：云主机**稍后再买**（见下方大厂盘问第 6 条）；本轮先做到「本机 + 局域网可演示」，独立容器 + 新端口的设计不变。
9. **信息架构**：底部 **4 Tab**（首页 / 档案 / AI 管家 / 我的）；二级页：注册登录、宠物建档/编辑、打卡录入、消息中心、AI 对话与记录、服务者列表/详情、选服务项与号源、预约确认、我的预约与取消。
10. **AI 回答每条带合规标识**；红色等级置顶「就医准备清单」。
11. **演示数据**：种子演示账号（手机号+密码，2 只宠物 + 数十天记录 + 评分 + 若干预警）与现场注册闭环**两者都备**。
12. 一期遗留**本轮顺带收尾**：T1–T13 补结案关闭；#7 / #9 / #10 结案。
13. **技术栈**：Vue 3 + Vant 4 + Vite；色彩与字号沿用交付文档第三卷。

### 已确认的决策（大厂规划盘问，2026-09-23，共 22 问）

**观测与合规**

1. **埋点**：建 `app_event` 表记四类行为（注册 / 打卡 / AI 咨询 / 建预约），运营端加只读统计页（可派生活跃与留存）。→ ADR-0012
2. **合规三件套**：注册页勾选《用户协议》《隐私政策》+ 账号注销 + 手机号脱敏。→ ADR-0013
3. **密码找回**：无短信通道，走**运营端重置**（沿用一期「重置 + 强制改密」模式），C 端登录页写明。
4. **运维底线**：每日 `mysqldump` 保留 7 天 + 恢复演练、后端日志落卷、`/system/health` 外部探活；不上监控平台。→ ADR-0012
5. **HTTPS**：演示档沿用 **IP + HTTP**（免备案），风险显式记录（密码明文过网、浏览器可能提示不安全）；域名 / HTTPS / 备案归入上线档。→ ADR-0013
6. **云主机**：**稍后再买**（选型结论已有：腾讯云轻量锐驰型 2核4G/50G，65 元/月）。本轮先本机 + 局域网验证。
7. **git 纪律**：**每票一分支**（`t/<票号>-slug`），完成前跑四套验证，通过后合回 `main`；不强制 PR。
8. **交付物**：先补**操作手册**（含 C 端章节与截图），**演示视频后补**。
9. **服务者可见性**：不做授权（PIPL 下无授权流程不能直接开放健康档案），改由**预约备注**（`appointment.remark`，字段已有）让用户主动告知。
10. **资源护栏**：宠物上限 5 只；头像 ≤ 2MB、AI 图片客户端预压到 ~1300×1300；**不做 UGC 审核**（图片不公开传播）。
11. **性能口径**：冒烟计时（首页 < 2s、AI < 5s P95）+ 首屏体积预算；**不做 500 并发压测**。→ ADR-0013
12. **质量口径**：不追覆盖率数字，以四套行为验证为准，差异在对照表写明。→ ADR-0013

**产品与安全**

13. **会话策略**：C 端 token **30 天**（后台维持 8 小时）+ `app_user` 失效版本号（改密 / 注销 / 全端登出即失效）。→ ADR-0011
14. **档案页加两条趋势图**：体重折线 + 打卡完成度柱状（近 30 天）。
15. **剩余时间投向**：**加固与交付齐备**（四套验证、可演示环境、手册与截图、演示前自查）；上线路径调研与功能扩展**本轮不做**。
16. **意向反馈三项**：等交付物齐备后再回（那时「MVP 预估」有真实数据对照）。
17. **需求对照表**：新建统一对照表，把交付文档八卷逐条标「已实现 / 有差异 / 出局 + 出处」。
18. **手机号语义**：定义为「登录手机号」（演示档不验证），配**注册/登录最小限流**（同 IP 每小时 N 次，429）。
19. **留存期限**：网络日志 ≥ 6 个月（法定）、AI 咨询记录 12 个月到期删除/匿名化（**清理任务要落地**）、健康数据至注销、第三方模型委托处理记录 ≥ 3 年。→ ADR-0012
20. **AI 成本**：靠每日配额 + 未配 key/调用失败走规则兜底；文档写成本估算与上限，**不做代码熔断**。→ ADR-0013
21. **代码交付**：做**打包脚本**（源码 + 手册 + 文档，排除 .git/依赖/构建产物），按公司要求再决定是否发 collaborator 邀请；**不开公开仓库**。
22. **演示环境不设防**：保留真实注册（验收要测「模拟真实用户场景」），演示前跑一次**数据重置**。

### 按默认生效（用户未反对，如要改请提）

- C 端不做「我的订单」独立页——订单信息并入预约详情（佣金规则不对用户展示）。
- AI 对话历史放在 AI 管家页内，不进消息中心。
- 上门类服务地址：默认取 `app_user.address`，下单页可覆盖。
- 预约规则完全沿用一期：14 天窗口、只校时间冲突、取消必填理由、不扣费。
- **历史打卡不可改**（只可改当日；历史靠时间轴如实呈现，不提供补签）。
- 前端**不做错误上报 SDK**（保留错误边界与「不白屏」纪律）；不做数据导出/可携带、不做改绑手机号。
- 后台界面本期不动（列表按 `source=SELF` 筛选属小改，可做）。
- 不做深色模式、不做多语言；不做灰度发布（无真实用户）。
- 客服与联系方式写在协议页里，不做工单系统。
- 演示账号与现场注册两条路径在演示脚本里都保留。

### 纪律与素材

- **契约先行**：先冻结 `docs/design/api-contract.md` 的 C 端章节，前后端各会话都按它写。
- **每票一分支**（见上）；**四套验证扩到 C 端**（后端测试 / 端到端冒烟 / UI 联调真渲染断言 / 前端构建）。
- 数据范围**服务端强制**；越权 403；金额是字符串；枚举大写；时间带时区。
- 术语一律用 `CONTEXT.md`（C 端带来的新词已补齐）。
- UI 规范沿用交付文档第三卷，移动组件映射到 Vant。
- 合规标识与留存口径以 `docs/research/ai-content-labeling-compliance.md`（核实日期 2026-09-23）为准。

### 环境（本机坑）

- `gh` 走 `~/.local/bin/gh`（Bash 工具里必须写全路径，且 gh 命令要加 `< /dev/null`，否则会吞 stdin 导致脚本静默中断）；`--body-file` 只认 Windows 形式路径。
- Docker 走 `~/.local/bin/docker` wrapper；挂 WSL 路径用 UNC 形式；npm 依赖装 Linux 版（容器内跑 dev/build），registry 用 npmmirror。
- 部署手册 `docs/design/deploy-runbook.md`；远端自检 `scripts/remote-selfcheck.sh`。

## Out of scope

- **微信小程序 / APP 客户端** —— 个人主体不可行（9/23 核实）；C 端形态已定为 Web + H5。
- **真实支付通道、在线兽医转人工付费、订阅/优惠券/邀请裂变**（模块 D）—— 无企业主体、无支付载具。
- **社区、商城、宠物用品推荐、服务评价与商家排名** —— 依赖内容与评价人。
- **微信登录 OAuth、微信 JS-SDK（分享卡片/公众号）、微信订阅消息推送** —— 均需认证主体。
- **短信验证码** —— 无通道（一期已定）。
- **地图 / 定位 / 距离排序、附近医院推荐**。
- **8 类主动提醒**（天气/疫情/趋势等）与提醒设置页 —— 消息中心只收预警与预约状态。
- **服务者查看健康档案的授权机制** —— 本轮不做（无授权流程即不能开放健康数据）；改由预约备注承担「主动告知」。
- **性能压测（500 并发）、单测覆盖率门槛、灰度发布** —— 无真实用户与并发，改为冒烟计时 + 体积预算 + 四套行为验证（ADR-0013）。
- 多语言、深色模式、离线能力；数据导出/可携带；改绑手机号。
- 服务者端 / 运营端的功能扩展 —— 本期只做 C 端（后台除来源筛选等小改外保持现状）。
