# 演示环境：Cloudflare 快速隧道 + 临时公网地址（不做公网部署）

上位决策是 [ADR-0002](0002-offline-payment.md)（到店付，平台不经手资金；支付对接待甲方澄清）
与 [ADR-0003](0003-lean-middleware.md)（中间件只有 MySQL + Redis）。本 ADR 只定**演示 / 验收时怎么给人
一个能点开看的地址**，不动生产部署的账（那要等甲方先定服务器、域名与对接范围）。

落地位置：仓库根 `online.sh`（起全栈 + 三条隧道 + 自检 + 收尾）、`open.sh`（AI 端口可配 `AI_PORT`）、
README 的「在线演示」一节。

## 问题：交付要一个「能点开看」的地址，但手里没有可部署的目标

三端 + 后端 + AI 服务跑在**真实 MySQL/Redis** 上（ADR-0014 起接口测试也跑真库）。要给人一个在线地址，
路只有两条：

1. **公网部署**：租服务器、买域名、配 HTTPS，把中间件与四个进程全搬上去。成本不只是一台机器——
   还有账号、国内域名的备案、以及此后每个演示版本都要重新发布一遍。而本项目现在的交付形态是
   「本地全栈 + 演示视频 + 操作手册」，服务器只有在甲方明确要的时候才有意义；
2. **把本机映出去**：隧道做转发，服务留在本机。

## 决定

**一、演示走 Cloudflare 快速隧道（免账号），域名是临时的（`*.trycloudflare.com`）。**
`./online.sh` 一条命令：全栈没起就先起（`open.sh --no-browser`）→ 并行拉起三条隧道（C 端 / 服务者后台 /
运营后台各一条，三端口各有自己的 URL）→ 逐条真访问验证 → 打印三个地址。

**二、这条通道是演示通道，不许被当成部署。** 边界写进脚本头注释与 README：关机 / 休眠 / 断网就不在线；
重启隧道换域名；地址谁拿到谁就能进，所以只放演示数据。

**三、验证口径是「端到端可用」，不是「端口通了」。** 每条隧道都验一条**免登录**接口
（`/api/v1/app/catalog/categories`，ADR-0037 第一节），因为「页面 200」只证明 Vite 活着——
照片传不上、审核页图片全裂这类问题恰好发生在它后面一层（切片 #95 与两个后台的 dev 代理都踩过）。

**四、隧道必须带 `--http-host-header localhost:<端口>`。** Vite 7 会校验 Host 头，不带这个头，
隧道域名会被 403「Blocked request」挡在门外；带上之后 Vite 看到的 Host 与本机开发完全同路。

## 代价与已知问题（写清楚，免得下一个人以为它坏了）

- **首次打开某页要等几秒到十几秒**：dev server 按需编译（2026-10-06 实测首页 12s、服务页 4s；
  点过一遍模块就进了 Vite 的内存缓存，之后明显变快）。要更快只能是构建产物 + 静态服务，那是另一条路。
- **本机到 Cloudflare 边缘的网络会抖**：实测同一分钟里一条能通、一条 dial timeout。
  所以脚本的策略是「并行拉起 + 每轮最多等 `TUNNEL_WAIT` 秒（默认 150）+ 不通换协议（quic ↔ http2）重试」——
  秒级判死等于把本来能救活的隧道亲手掐了。
- **要固定域名、不依赖本机**，只能回到「公网部署」那条路：服务器 + 域名 + 账号，等甲方定。
