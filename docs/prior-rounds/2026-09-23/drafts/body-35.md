## Parent

#25（地图：C 端（Web + H5）——用户自助侧可演示产品）

## What to build

把一期的「四套验证」扩到 C 端，防止「构建过但页面白」这类只有真渲染能抓的问题：

- **UI 联调自动测试**：仿 `scripts/check-ui.sh` 新增 C 端脚本（未登录落到登录页、4 Tab 与二级页真渲染断言、登录后首页 / 档案 / AI / 消息 / 服务各页有内容），**两条路径都跑**（dev 与构建产物 + 反代）。
- **冒烟脚本扩展**：`scripts/smoke-demo-path.sh` 增加 C 端主线（注册 → 建档 → 打卡 → 档案 → AI 问答 → 消息 → 浏览与建单 → 取消）。
- 前端构建纳入每次验证。

## Acceptance criteria

- [ ] 新增的 C 端 UI 联调脚本对**两条路径**（dev / dist）都跑通
- [ ] 冒烟脚本的 C 端主线在跑起来的整套服务上一次通过
- [ ] 脚本用法写进 `README.md` 命令速查

## 补充（2026-09-23 大厂规划盘问）
