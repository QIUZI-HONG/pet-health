# 第八批裁决：社区形态、安全收口、测试口径、性能口径

四条互不依赖，合并（同 [ADR-0024](0024-quota-care-community-tracking-packages.md)）。

## 一、社区（挡 [#72](https://github.com/QIUZI-HONG/pet-health/issues/72) → #117）

- **三种内容**：经验卡片（用户录入打卡/就医记录后可**一键生成匿名卡片**）、慢病社群（按慢病标签聚合的帖子流）、问答互助（提问 / 回答 / 采纳）。
- **不做独立 Tab**：嵌在首页与档案页的侧栏（[ADR-0016](0016-c-end-desktop-ia.md) 的桌面 IA 已经这么排）。
- **发文权限走权益码 `community.post`**（[ADR-0038](0038-order-redeem-rights-points.md)）。
- **内容进审核**：机审敏感词 + 运营下架（权限矩阵里「内容审核」归运营，[ADR-0037](0037-roles-console-boundary-coupon-pool.md)）。
- 经验卡片**默认匿名**（交付文档 F020「录入即生成卡片（匿名）」）。

## 二、安全收口（挡 [#81](https://github.com/QIUZI-HONG/pet-health/issues/81) → #121）

- **已落**：统一限流、操作审计、写接口幂等（[ADR-0028](0028-security-baseline.md)）；字段加密与脱敏（[ADR-0013](0013-field-encryption.md)）。
- **待补三件**（本 ADR 确认这是安全收口的全部范围）：
  1. **越权矩阵测试**——角色 × 资源 × 操作逐格，这是权限矩阵（ADR-0037）落地后**唯一能证明它有效**的方式；
  2. **依赖漏洞扫描进 CI**（一条命令的成本）；
  3. **真渗透测试**列进上线前置清单（需外部工具与真实部署，属 #121/#122）。
- **不做**：WAF、国密算法、等保改造。没有合规要求驱动，而且国密会牵动现有加密与哈希体系——做了既不被验收认，又增加风险。

## 三、测试口径（挡 [#82](https://github.com/QIUZI-HONG/pet-health/issues/82)）

- **三层**：单元（值对象、纯函数、分期与计算逻辑）、集成（Testcontainers 起真实 MySQL/Redis）、契约（前端生成物同步 + 后端 DTO 与契约字段对比）。
- **取消全局覆盖率门禁**。理由：聚合报告的分母含 DTO 与配置类（`ph-api.app` 一个包 720 条指令、100%），设 60% 门禁的实际效果是逼人写无意义用例。改为**评审口径**——「新增模块的关键服务必须有用例」，覆盖率报告**只出数、不设门槛**。
- 性能与安全用例**单独归类**，不混进集成测试按条数考核。
- `packages/shared` 仍缺独立测试 runner（当前请求层由 C 端代跑），属 #82 范围内的待办。

## 四、性能与容量口径（挡 [#83](https://github.com/QIUZI-HONG/pet-health/issues/83)）

**把无法核对的承诺改成可核对的**：

- 接口 `P95 < 500ms` → **按接口门槛化**（列表、详情各一条），依据是已有基线：读接口 p95 4–21ms、写 p95 39ms、20 并发 0 错误（`server/scripts/perf-smoke.py`）。
- **AI 问答不承诺 3 秒**：延迟由供应商主导（中位 5.3s、偶发 20s、P95 7.4s），依据 [ADR-0017](0017-model-provider-deepseek.md)。
- **「支持 500 并发」改为「按 500 并发反推连接池与线程配置」**并记录在案，**不宣称实测过**（没有生产环境就测不出容量结论）。
- 容量配置结论进部署前置条件（[#122](https://github.com/QIUZI-HONG/pet-health/issues/122)）。

## Consequences

- 交付文档 9.3 的三条性能指标按上述改写，验收时要主动说明（否则会被当成「没达标」）。
- 覆盖率不再当门禁之后，**评审必须真的看用例**；否则这条口径调整会变成「降低标准」的同义词。
- 渗透测试做之前，安全只能说「已实现」，不能说「已验证」——这句话在验收会上要守住。
